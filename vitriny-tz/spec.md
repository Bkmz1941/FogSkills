# Витрины — карта ТЗ (части 1–5)

Структурный слепок. Корнеры вынесены в [corners.md](corners.md), модель/статусы/роли — в [model.md](model.md).

Иерархия сущностей: **Экран (папка)** → **Витрина** (Родительская) → **Подвитрина** (слой) → внутри витрины: **Секции** → **Элементы/Баннеры** (медиа).

---

## Часть 1. Раздел «Экраны» (главный дашборд)

Таблица всех экранов (папок).

### Над таблицей
- **Поиск:** по названию экрана и System ID.
- **Фильтры:** по статусу (Ожидает / Частично / Подключено), по приложению (iOS, Android, Web…).
- **Кнопка «+ Добавить экран»** (шторка/модалка/экран). Поля при создании:
  - Имя экрана (лимит символов).
  - Приложения — галочки, **только из заведённых в проекте**. Модалка обычная, **но без min/max версий** (Корнер 1).
  - Описание (необязательное, лимит символов).
  - После сохранения экран появляется в таблице со статусом 🟡 **Ожидает**.

### Столбцы таблицы
Имя экрана (кликабельно → внутрь к витринам) · Описание · Приложения (иконки+название) · Статус (Ожидает/Подключено/Частично) · Кол-во витрин (включая дефолтную, Корнер 2) · Действия (⋮).

### Меню «⋮» экрана
- Скопировать System ID (микро-алерт «Скопировано»).
- Настройки экрана (= форма создания): имя, описание, список приложений (можно докинуть), System ID — readonly.
- Перейти в витрины.
- Статус интеграции — попап со свитчерами по платформам для подтверждения подключения.
- Открыть документацию (Swagger/Confluence в новой вкладке).
- Удалить — блокируется при наличии активных витрин внутри (Корнер 7).

## Часть 1 (продолжение). Внутри Экрана — список витрин

### Табы (строгое разделение потоков)
- **[ Активные ]** — боевая зона. Витрины со статусами 🟢 Активна и 🟡 Запланирована. **Только здесь** работает Drag-and-Drop приоритета (верхняя перекрывает нижние).
- **[ Неактивные ]** — склад. Витрины 🔒 Скрыта, ⚪️ Завершена, 🟠 Черновик. D&D отключён, сортировка по дате (свежие сверху).
  > ⚠️ Неоднозначность: местами в ТЗ этот таб называется «Архив». См. decisions.md → Q1.

### Столбцы витрин
Название (кликабельно → редактор) · Период показа · Сегменты · Теги · Дата · Языки (RU/KZ/EN) · Статус (вычисляемый бейдж) · Действия (⋮). Порядок столбцов — по визуалу.

### Меню «⋮» витрины
1. Редактировать (конструктор). 2. Опубликовать/Скрыть (меняет статус + перекидывает между табами). 3. Дублировать (Корнер 2 Части 2). 4. Скопировать UUID. 5. Удалить (запрещено для Активна/Запланирована).

### Дефолтная витрина («Фоллбек») — Часть 1, 2.4
Генерируется автоматически при создании Экрана. **Неприкосновенна** (см. инвариант 3). Подробности — corners.md → INV-DEFAULT.

### Кнопка «+ Создать витрину» и фильтры
- Новая витрина по умолчанию → статус ⚪️ Черновик, таб Неактивные/Архив.
- Фильтры/поиск — **над табами**, но применяются локально к активному табу (Корнер 8).
- Фильтры: Поиск (название) · Статус (мультиселект, зависит от таба) · Сегменты · Теги · Период.

## Часть 2. Создание витрины (Паспорт)

Кнопка «+ Добавить» → страница создания, по умолчанию статус ⚪️ Черновик.

**Главный переключатель — Тип витрины (радио):** Родительская / Подвитрина. От него зависит вся логика полей. Рядом — UI-подсказки про родителя/подвитрину и правило наследования.

### Сценарий А: Родительская витрина — поля
1. Название (*) — 0/30 символов.
2. Приложения (*) — кнопка «+ Добавить приложение». В списке **только прилы текущего Экрана**. Модалка без min/max версий. Тултип: «Приложения выбираются из того экрана, где вы находитесь».
3. Время показа — дата/время начала/окончания + таймзона. Для черновика время необязательно (Развилка 2).
4. Сегменты (*) — «+ Добавить сегменты». Тултип: «Для глобальной витрины необходимо выбрать все сегменты, в том числе для подвитрин» (аудитория родителя — входная дверь).
5. Языки (*).
6. Теги — из выпадающего списка.

### Сценарий Б: Подвитрина (наследование)
Появляется обязательный дропдаун «Родительская витрина» (только родительские витрины этого экрана). Пока родитель не выбран — все поля заблокированы, Сохранить disabled (тултип «Укажите родительскую витрину»).

После выбора родителя включаются правила наследования (**только сужение**):
1. Приложения — автозаполнены чипсами родителя; можно только удалять (крестик), не добавлять.
2. Время показа — календарь ограничен датами родителя; таймзона наследуется (readonly).
3. Сегменты (*) — только из сегментов родителя.
4. Языки (*) — автозаполнены; можно только сужать.

Корнеры Части 2 → corners.md (C2-1…C2-4).

## Часть 3. Наполнение витрины (таб «Внешний вид» / Конструктор)

Конструктор = **Секции** (контейнеры) + **Элементы/Баннеры** (контент).

### 3.0 Пустое состояние
- Родительская новая: только кнопка [ + Новая секция / + Добавить секцию ] → модалка «Настройки секции»:
  1. Тип секции (*) — Баннеры / Сторис / Кастомная (определяет визуал и механику на проде).
  2. Имя секции (*) — с мультиязычным селектором (переводы).
  3. Свитчер «Отображать клиенту имя секции» (вкл = заголовок над каруселью; выкл = только техническое имя).
- Подвитрина новая: НЕ чистый лист — показан заблокированный каркас родительских секций («Якоря»), кнопка добавления — между/под ними (C3-якоря).

### 3.1 Управление секциями
Добавление · D&D-сортировка (за левый край) · сворачивание · скрытие (глазик-свитчер) · настройки (шестерёнка: тип, имя). В развёрнутом виде баннеры скроллятся горизонтально.

### 3.2 Добавление контента (развилка)
[ + Добавить элемент ] → выбор: **Новый** (уход в Контент→создание баннера, черновик витрины сохраняется) / **Выбрать из существующих** (Библиотека). В «существующих» — умный фильтр платформ (C3-фильтр).

### 3.3 Периоды показа баннера
Мульти-периоды («+ Добавить период»), date picker (начало/конец, чекбокс «без даты завершения», таймзона с поиском). Инфо-плашка: редактирование самого баннера — в разделе Контент. Валидация дат: период баннера ⊆ период витрины (C3-даты).

### 3.4 Состояния баннеров в конструкторе
- Hover-оверлей: настройка периода · удаление (с подтверждением) · D&D.
- Авто-схлопывание платформ: если баннер поддерживает меньше платформ, чем витрина — лишние гасятся серым + тултип «Отключено: исходный медиа-файл не поддерживает платформу».
- Статус «Завершен»: по истечении периода — тёмный оверлей «Период показа завершен» (остаётся для истории, на прод не отдаётся).
- Иконки приложений: максимум 3 + бейдж «+N»; ховер → тултип со списком ВСЕХ прил баннера.

### 3.5–3.6 Мультиязычность
- Дропдаун языков (правый верх) — только превью локали, не меняет таргетинг.
- Фоллбек: нет перевода для языка → дефолтный язык с пометкой.
- **Запрет публикации пустых языков**: заявлен язык → не может быть пустым (C3-lang).
- Кнопка «Скопировать контент» (донор — дефолтный язык, клонирует сетку+баннеры). После копирования/ручного добавления:
  - Кейс А (есть перевод медиа) — авто-подтягивается, действий не нужно.
  - Кейс Б (нет перевода) — жёлтый actionable warning ⚠️: [ Использовать дефолтную версию ] / [ Удалить элемент ].

### 3.7 Реакция конструктора на изменения паспорта
Сценарии 1–4 (добавил язык / добавил прилу / сузил период / публикация без дат) → corners.md (C3-react-1…4).

### Корнеры подвитрины в конструкторе
C3-pod-1…6 → corners.md.

## Часть 4. Таб «Настройки» (редактирование Паспорта)

Дублирует экран создания, но с read-only защитами:
- **Тип витрины** — всегда read-only.
- **Родительская витрина** (для подвитрин) — всегда read-only (перепривязать нельзя).
- Название — редактируется всегда.
- Приложения: родитель — add/remove в рамках Экрана; подвитрина — только сужать.
- Время/таймзона — редактируется (с проверками конфликтов).
- Сегменты/Языки: родитель — add/remove; подвитрина — только сужать.
- Теги — редактируются.

Корнеры 4.2 → corners.md (C4-1…3): сужение дат, добавление языка, удаление параметров у родителя.
