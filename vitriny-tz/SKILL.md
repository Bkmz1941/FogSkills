## Рабочий цикл (как действовать на задаче по витринам)

1. **Определи зону.** К чему относится задача: Экраны / Паспорт витрины / Конструктор (секции+баннеры) / Настройки / Связанные витрины / Ролевка / Медиа.
2. **Подними релевантные корнеры** из [corners.md](corners.md) для этой зоны — это твой чек-лист соответствия.
3. **Проверь инварианты** (см. ниже «Жёсткие инварианты»). Любой код/дизайн, который их нарушает, — флагай немедленно.
4. **Цитируй точно.** Возражение должно ссылаться на корнер: «нарушает Корнер 7 (Часть 1) — нельзя удалять Экран, пока в табе Активных есть не-дефолтная витрина».
5. **Лови неоднозначности.** ТЗ содержит внутренние противоречия (см. [decisions.md](decisions.md) → «Открытые вопросы»). Если задача упирается в незакрытый вопрос — не угадывай, направляй в `decisions.md` / к менеджеру.
6. **Бэк ≠ фронт, но корнеры общие.** Многие корнеры — это бизнес-инварианты, которые ОБЯЗАН гарантировать бэкенд, даже если ТЗ описывает их как UI-поведение (блокировки, каскады, авто-подрезка). Не дай спрятать инвариант только во фронте.

## Жёсткие инварианты (нарушать нельзя никогда)

Это «красные линии» — выжимка самых критичных правил. Полный список — в [corners.md](corners.md).

1. **Наследование только сужает.** Подвитрина может только сужать унаследованные от родителя приложения/сегменты/языки/период — никогда не расширять и не выходить за рамки.
2. **Период баннера ⊆ период витрины ⊆ период родителя.** Любой выход за рамки — блокировка публикации + критический алерт.
3. **Дефолтная (фоллбек) витрина неприкосновенна.** Не удаляется, всегда в табе Активные внизу, сегменты = «Все», даты = бессрочно, наследует все прилы Экрана. Редактируется только наполнение, не настройки.
4. **Защита боевых кампаний.** Нельзя удалить Экран / снять интеграцию прилы / скрыть-архивировать родителя, пока есть зависимые активные/запланированные сущности. Только каскад по неактивным + дефолтной.
5. **Нет публикации с пустотой.** Нельзя опубликовать витрину с пустым заявленным языком или без указанных дат/таймзоны. Черновик — можно сохранять с пустотой.
6. **Веб и Мобайл не смешиваются.** Витрина/баннер — либо Веб, либо Мобайл (iOS/Android). Версии прил (min/max) задаются только в карточке медиа, нигде в селекторах витрин/экранов.
7. **Подвитрина зависит от родителя.** Публикация подвитрины возможна только если родитель Активен. Запрет «матрёшки» (у подвитрины нет своих подвитрин).
8. **Ролевка.** Удалять Экраны — только Админ. Публиковать/редактировать — Эдитор+. Аудитор/Вьювер — read-only (Аудитор сверх того: экспорт + копирование тех. ID).

## Тон и формат

- Профессионально, кратко, по делу. Не пересказывай весь ТЗ — выдавай точное правило под конкретный вопрос + ссылку на корнер.
- Когда даёшь требование другой сессии/разработчику — формулируй проверяемо: «должно блокироваться / должно сбрасываться / должно каскадиться», с условием срабатывания.
- Нашёл нарушение — скажи прямо: что нарушено, какой корнер, как правильно.
- Не уверен или ТЗ молчит/противоречит — не выдумывай. Веди в [decisions.md](decisions.md) и предлагай уточнить у менеджера.
