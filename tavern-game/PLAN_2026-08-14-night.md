## Первый шаг после перезапуска

1. Проверить мост: `claude mcp list | grep -i unity` (порт 8090). Если
   лежит — Window → MCP for Unity → Start bridge.
2. Прогнать компиляцию (вне play) и `read_console` — должно быть чисто.
3. Смоук в play: поставить клумбы рядом (слияние), покрасить группу,
   Shift+колесо на газоне над клумбой, Del на выделении.
4. Коммитить пачкой (только свои файлы, чужие ханки — выборочно):
   - `feat(build): клумба-модуль со слиянием + газоны 2×2/3×3`
   - `feat(build): Shift+колесо — вертикаль для любых объектов с опорой`
   - `feat(build): покраска — верх стены дефолтный, торец угла с фасадом`
   - `feat(ui): Del удаляет выделение стройки`
   - `perf(build): клумба одним мешем, кортежные ключи кеша, NonAlloc-лучи`
   - `fix(ui): призрак инвентаря не рисуется вне поля ячеек`

## Главная незакрытая находка: GC ~180 КБ/кадр

Замерено пробником (ProfilerRecorder «GC Allocated In Frame», среднее по
окну кадров): игра в установившемся режиме мусорит **164–208 КБ/кадр**,
пик ~250 КБ. Это ~11 МБ/с при 60 fps ⇒ регулярные сборки и микрофризы.
Проверено, что MCP-мост тут ни при чём: на паузе редактора остаётся
~4 КБ/кадр.

Источник НЕ найден. Что уже отсеяно:
- Счётчик за один кадр (`get_counters`) и дельта Mono-heap — оба слишком
  шумные, дают противоречивые знаки; доверять только окну ProfilerRecorder.
- Статически чисты: `GridView.Update`/`ApplyState`, `WallCutaway`,
  `DoorPiece.Update`, `BuildQuery` (везде NonAlloc-физика).
- A/B-скан по 36 типам с кадровыми методами прогнать не удалось: другая
  сессия параллельно управляет редактором (несколько раз выбивала из play
  посреди скана).

Как продолжить (когда редактор свободен):
1. Вернуть пробник: класс с `ProfilerRecorder.StartNew(ProfilerCategory.

3. Подозреваемые по первому (шумному) прогону, проверить в первую
