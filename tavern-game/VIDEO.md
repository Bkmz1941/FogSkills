## ⭐ ПРАВИЛО СКЛЕЙКИ (Илья 2026-09-06: «будем всегда им следовать»)

Один проход ffmpeg делает всё сразу — иначе каждый лишний прогон это лишнее
пережатие. Порядок фильтров: привести входы → переходы → 1080p и звук → один
энкод.

1. **Каждый вход** приводится к общему виду:
   `fps=<общий>,scale=1920:1080:flags=lanczos,setsar=1,setpts=PTS-STARTPTS` и
   `aresample=48000,aformat=channel_layouts=stereo,asetpts=PTS-STARTPTS`.
   Общий fps — тот, что у ВСЕХ дублей, если он у них одинаковый (папка 1 —
   25 к/с, папка 2 — 30 к/с); разнобой приводить к большему. Насильно гнать
   25 к/с в 30 нельзя: кадры задвоятся и появится дёрганье.
2. **Переходы** — цепочка `xfade=transition=fadeblack:duration=1` со
   смещениями накоплением (формула ниже) и `acrossfade=d=1:c1=tri:c2=tri` для
   звука.
3. **Всегда 1080p**, даже если исходники 720p. Деталей апскейл не добавляет,
   но ютуб выделяет потоку 1080p заметно больший битрейт, и картинка на выходе
   чище. Масштабировать ВНУТРИ склейки, а не вторым прогоном.
4. **Звук после переходов**:
   `acompressor=threshold=-20dB:ratio=4:attack=15:release=220:makeup=2,loudnorm=I=-14:TP=-2`.
   Просто поднять громкость нельзя — пики голоса и так стоят на нуле.
5. **Энкод**: `-c:v libx264 -pix_fmt yuv420p -profile:v high -level 4.2
   -preset slow -crf 18 -c:a aac -b:a 192k -movflags +faststart`.

## Рецепты ffmpeg

Паспорт файла:

```bash
ffprobe -v error -show_entries format=duration,size:stream=codec_name,profile,pix_fmt,width,height,r_frame_rate,sample_rate,channels -of csv=p=0 in.mp4
```

Раскадровка 12 кадров плиткой 4×3 (длительность подставить):

```bash
ffmpeg -y -i in.mp4 -vf "fps=12/DUR,scale=480:-1,tile=4x3" -frames:v 1 sheet.png
```

Спектрограмма (речь — полосы ниже 4 кГц с паузами) и мера движения
(средняя разность кадров; ~0,005 значит статичный план):

```bash
ffmpeg -y -i in.mp4 -lavfi "showspectrumpic=s=1200x300:legend=1" spec.png
ffmpeg -i in.mp4 -vf "tblend=all_mode=difference,signalstats,metadata=print:key=lavfi.signalstats.YAVG" -f null - 2>&1 | grep -o 'YAVG=[0-9.]*'
```

Склейка двух дублей с секундным переходом. `OFF` = длина A минус длительность
перехода. `fadeblack` — затухание в чёрное и появление (Илья выбрал его);
`fade` — растворение одного плана в другой. Звук перетекает через
`acrossfade` за ту же секунду. Оба входа приводятся к одному fps и одному
формату звука, иначе фильтры не стыкуются.

```bash
ffmpeg -y -i A.mp4 -i B.mp4 -filter_complex \
 "[0:v]fps=25,setpts=PTS-STARTPTS[v0];[1:v]fps=25,setpts=PTS-STARTPTS[v1];\
  [v0][v1]xfade=transition=fadeblack:duration=1:offset=OFF,format=yuv420p[v];\
  [0:a]aresample=48000,aformat=channel_layouts=stereo,asetpts=PTS-STARTPTS[a0];\
  [1:a]aresample=48000,aformat=channel_layouts=stereo,asetpts=PTS-STARTPTS[a1];\
  [a0][a1]acrossfade=d=1:c1=tri:c2=tri[a]" \
 -map "[v]" -map "[a]" -c:v libx264 -pix_fmt yuv420p -profile:v high -level 4.0 \
 -preset medium -crf 18 -c:a aac -b:a 192k -movflags +faststart joined.mp4
```

⭐ `format=yuv420p` ПОСЛЕ xfade и `-pix_fmt yuv420p -profile:v high` — обязательны.
Без них xfade договаривается о yuv444p, libx264 пишет профиль High 4:4:4, и
плеер показывает чёрный экран или «нет видео» (P156). Проверка после каждой
склейки: `ffprobe … pix_fmt` должен вернуть `yuv420p`, профиль `High`.

Проверка перехода по кадрам (номер кадра = секунда × fps):

```bash
ffmpeg -y -i joined.mp4 -vf "select='eq(n\,730)+eq(n\,745)+eq(n\,751)+eq(n\,770)',scale=480:-1,tile=4x1" -vsync vfr -frames:v 1 check.png
```

Проверено 2026-09-02: два дубля по 30 и 41 секунде, `fadeblack` на 29,5–30,5 с,
результат 70,9 с, 6 МБ, играет у Ильи.

### Цепочка из N дублей (2026-09-06)

Для трёх и более дублей смещения считаются накоплением, руками не набирать —
сгенерировать. Смещение k-го перехода = (длина склейки до него) − D, где длина
после каждого перехода растёт на длительность нового дубля минус D. Итоговая
длина = сумма длительностей − D × (число переходов).

```python
acc = durs[0]; vprev, aprev = 'v0', 'a0'
for i in range(1, len(names)):
    parts.append('[%s][v%d]xfade=transition=fadeblack:duration=%g:offset=%.6f[vx%d]' % (vprev, i, D, acc - D, i))
    parts.append('[%s][a%d]acrossfade=d=%g:c1=tri:c2=tri[ax%d]' % (aprev, i, D, i))
    acc += durs[i] - D
    vprev, aprev = 'vx%d' % i, 'ax%d' % i
parts.append('[%s]format=yuv420p[v]' % vprev)
```

Каждый вход перед этим приводится к общему виду:
`[i:v]fps=30,setpts=PTS-STARTPTS[vi]` и
`[i:a]aresample=48000,aformat=channel_layouts=stereo,asetpts=PTS-STARTPTS[ai]`.

**Проверять переход не по номерам кадров, а сканом яркости.** Скан находит все
провалы разом и не зависит от арифметики:

```bash
ffmpeg -hide_banner -loglevel info -i joined.mp4 \
  -vf "fps=10,signalstats,metadata=print:key=lavfi.signalstats.YAVG:file=-" -f null - 2>/dev/null \
  | paste - - | awk '{split($3,a,":"); split($4,b,"="); printf "%.1f %.1f\n", a[2], b[2]}' \
  | awk '$2 < 12'
```

Должно найтись ровно столько тёмных моментов, сколько переходов. У `fadeblack`
картинка гаснет БЫСТРЕЕ, чем разгорается, поэтому самый тёмный кадр стоит не в
середине секунды, а примерно на её трети — это норма, а не сбитое смещение.

⚠️ **`-ss` ПЕРЕД `-i` для таких замеров не годится**: это быстрый поиск по
опорным кадрам, и время в выводе поедет — «переход» найдётся не там, где он
есть. Мерить полным сканом (как выше) или `-ss` ПОСЛЕ `-i`.

⚠️ **Звук короче видео — это из записи, а не из склейки.** У дублей
vokoscreenNG звуковая дорожка на 47–67 мс короче видеодорожки; в склейке
разницы складываются (на семи дублях 0,4 с). Тишина в самом хвосте, лечить
нечего.

Проверено 2026-09-06: семь дублей (28,3 + 46,8 + 16,0 + 23,4 + 46,1 + 38,4 +
39,9 с) склеены шестью переходами по секунде, результат 232,8 с, 37 МБ,
`yuv420p`/High, скан яркости нашёл ровно шесть провалов (2,3–6,6 из 255) на
27,5 / 73,3 / 88,2 / 110,6 / 155,7 / 193,1 с. Кодирование 19 секунд.

### Громкость дорожки (2026-09-06)

Илья: «а ты можешь звук громче сделать дорожку?» Просто поднять нельзя: у
дублей vokoscreenNG пики голоса уже стоят на нуле (в семи склеенных — 435
семплов на 0 дБ при средней −24 дБ и интегральной −18,5 LUFS), любое усиление
идёт в клиппинг.

Рабочая цепочка — сначала придавить пики, потом нормализовать:

```bash
ffmpeg -y -i joined.mp4 -c:v copy \
 -af "acompressor=threshold=-20dB:ratio=4:attack=15:release=220:makeup=2,loudnorm=I=-14:TP=-2" \
 -c:a aac -b:a 192k -movflags +faststart joined_loud.mp4
```

Результат на семи дублях: интегральная −15,4 LUFS (было −18,5), средняя
−20,2 дБ (было −24,0), пик −0,9 дБФС (был 0,0 с клиппингом), на нуле 2 семпла
вместо 435. Картинка не трогается (`-c:v copy`), поэтому пересборка занимает
секунды. Проверка после: `ebur128=peak=true` даёт `I` и `Peak`, `volumedetect`
— `mean_volume`, `max_volume` и `histogram_0db` (сколько семплов упёрлось в
ноль).

Две ловушки, обе поймал на этих же дублях:

- ⚠️ `loudnorm` с `linear=true` НЕ держит заявленный потолок: он применяет
  ровный сдвиг, и пики ушли на +0,8 дБФС. Нужен динамический режим (просто не
  писать `linear=true`).
- ⚠️ `alimiter` по умолчанию сам поднимает уровень обратно к лимиту
  (`level=enabled`), и с ним стало ХУЖЕ: 19 076 семплов на нуле. Либо
  `level=disabled`, либо, как здесь, лимитер вообще не нужен.
- Кодек AAC ещё и «звенит» сверху примерно на децибел, поэтому целиться надо
  на `TP=-2`, а не в ноль.

### Качество картинки: что можно и чего нельзя (2026-09-06)

Илья: «а качество видео улучшить?» Исходники — 1280×720, 30 к/с, около
2,5 Мбит с экранной записи. Больше деталей, чем в исходнике, не появится
никаким пережатием: склейка идёт на CRF 18, это визуально прозрачно.

Что реально помогает:

1. **Писать лучше.** Настройки записи из раздела выше: 1080p, 60 к/с,
   20–30 Мбит. Это единственный способ добавить деталей.
2. **Отдавать ютубу 1080p.** Апскейл `scale=1920:1080:flags=lanczos` деталей
   не добавляет, но ютуб выделяет потоку 1080p заметно больший битрейт, чем
   720p, и на выходе картинка чище. На этих семи дублях: 39 МБ в 720p против
   68 МБ в 1080p (2,36 Мбит), кодирование 29 с на `preset slow`.

```bash
ffmpeg -y -i joined.mp4 -vf "scale=1920:1080:flags=lanczos" \
 -c:v libx264 -pix_fmt yuv420p -profile:v high -level 4.0 -preset slow -crf 18 \
 -c:a copy -movflags +faststart joined_1080.mp4
```

### Вертикальный формат под Shorts: как писать в OBS (2026-09-06)

Shorts — это 9:16, то есть 1080×1920, до 3 минут. Горизонтальную запись
обрезать «в лоб» нельзя: у игры весь интерфейс по углам, и при обрезке до
9:16 от кадра 1920×1080 остаётся центральная полоса шириной примерно 607
пикселей, то есть треть ширины — углы с полосками здоровья и хотбаром уходят
целиком.

Три пути, по возрастанию качества результата:

1. **Писать как обычно 16:9, кадрировать потом.** Ничего не меняем в OBS, а
   вертикаль собираем на монтаже: под каждый кусок свой сдвиг окна обрезки,
   можно вести его за персонажем. Плюс — интерфейс не теряется, можно выбрать,
   что показать; минус — работа на монтаже.
2. **Вертикальный холст в OBS.** Настройки → Видео: базовое и выходное
   разрешение 1080×1920, 60 к/с. Источник игры → правый клик → Преобразование
   → Изменить преобразование: тип ограничивающей рамки «Масштаб по внешним
   границам», размер 1080×1920, выравнивание по центру — картинка заполнит
   вертикаль, лишнее по бокам обрежется. Быстро и без плагинов, но углы
   интерфейса срезаются.
3. **Игра сама рендерит вертикально.** Окно игры 1080×1920 (в редакторе —
   соотношение 9:16 в Game view, в сборке — параметры запуска
   `-screen-width 1080 -screen-height 1920`), интерфейс раскладывается под
   вертикаль сам. Картинка лучшая из трёх, но надо проверить, что UI не
   разъезжается на таком соотношении.

Настройки записи в OBS независимо от пути: Вывод → Режим «Расширенный» →
вкладка «Запись». Формат mkv (mp4 бьётся при падении OBS, потом ремукс в mp4
одной командой `ffmpeg -i in.mkv -c copy out.mp4`). Кодировщик x264 или NVENC,
управление битрейтом CRF/CQP, значение 18, интервал ключевых кадров 2 с,
профиль high. Звук: Настройки → Аудио → частота 48 кГц; микрофон и звук игры
по возможности на разные дорожки (в «Расширенном» это галочки дорожек у
источников) — тогда на монтаже можно поднять голос отдельно от игры.

Проверка после первой пробной записи — те же три числа, что у склейки:
разрешение и `pix_fmt`, частота кадров, пик звука ниже нуля.

### Замедление куска (2026-09-06)

Два способа, оба проверены на этих дублях:

```bash
# 1) простое: кадры дублируются, годится для 60 fps исходника
ffmpeg -y -i in.mp4 -ss 30 -t 4 -vf "setpts=2*PTS" -af "atempo=0.5" \
  -c:v libx264 -pix_fmt yuv420p -crf 18 slow.mp4          # 4 с -> 8 с, ~1 с работы

# 2) с достройкой кадров: плавно на 30 fps исходнике
ffmpeg -y -i in.mp4 -ss 30 -t 4 \
  -vf "minterpolate=fps=60:mi_mode=mci:mc_mode=aobmc:vsbmc=1,setpts=2*PTS" \
  -af "atempo=0.5" -c:v libx264 -pix_fmt yuv420p -crf 18 slow.mp4
```

Второй даёт 60 fps и настоящую плавность, но считает медленно: 4 секунды
исходника за 38 с, то есть примерно в 9-10 раз медленнее реального времени.
На быстром движении достроенные кадры могут «плыть», поэтому годится для
коротких вставок, а не для всего ролика. `atempo` ниже 0.5 за раз не умеет —
для более сильного замедления цеплять несколько: `atempo=0.5,atempo=0.5`.
