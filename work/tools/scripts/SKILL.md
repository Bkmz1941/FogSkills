# Наши скрипты

> ## ⛔ Правило по серверам
>
> **Любое действие на сервере — только по явной команде Ильи в текущем разговоре.**
>
> Это касается и изменений (установка, правка файлов, рестарт, деплой, чистка),
> и просто захода на сервер с чтением — `ssh`, `docker ps`, `dcps`, чтение логов.
> Разрешение разовое: дали на одно действие — оно не распространяется на
> следующее и не переносится на другой сервер.
>
> Общая формулировка вроде «разберись», «почини», «поддерживай в порядке»
> разрешением НЕ является. Если для задачи нужен сервер — сначала спросить,
> назвав конкретный сервер и конкретную команду.
>
> Установлено 2026-09-07.

Единое место хранения кастомных утилит. **Источник правды — `bin/` в этом
скиле**; всё, что стоит на машинах и серверах, — копии.

## Инвентарь

| Скрипт | Что делает | Где стоит |
|---|---|---|
| `bin/dcps` | `docker ps`: id / имя / статус / внутренний IP / порты / образ (коротко) | локально `~/.local/bin/dcps`<br>дев Olimp `95.179.244.240` → `/usr/local/bin/dcps`<br>прод Olimp `209.250.237.82` → `/usr/local/bin/dcps` |
| `bin/dci` | `docker images`: id / репозиторий / тег / размер / возраст | локально `~/.local/bin/dci`<br>дев Olimp `95.179.244.240` → `/usr/local/bin/dci`<br>прод Olimp `209.250.237.82` → `/usr/local/bin/dci` |

Оба пробрасывают аргументы в докер как есть.
Переименованы 2026-09-07: `dps`/`dpi` → `dc`/`di` → **`dcps`/`dci`**.
Промежуточное имя `dc` не прижилось — см. грабли про столкновение имён.

## `dcps`

```
CONTAINER ID  NAMES                STATUS                IP                     PORTS     IMAGE
1afaedff99bf  old-cms-dev-app-1    Up 12 days (healthy)  172.19.0.8,172.18.0.6  8000/tcp  monolith:f8e4cfe0b150
a45f81787d7d  old-cms-dev-redis-1  Up 4 weeks (healthy)  172.19.0.3             6379/tcp  redis:6.0.16-bullseye
```

**Колонка IMAGE — только имя и тег, без пути до реестра.**
`registry.agg.one/old-cms/monolith:f8e4cfe0b150b26a98f8b5ec017c0de08dd00e15`
превращается в `monolith:f8e4cfe0b150…`: префикс реестра срезается, а длинный
шестнадцатеричный тег (git-SHA) обрезается до 12 символов, как docker делает с
id. Осмысленные теги вроде `6.0.16-bullseye` остаются целиком — режется только
то, что длиннее 32 символов и состоит из одних hex-символов.

**Многоточие на конце значит «имя урезано, настоящее длиннее».** Маркер
добавили после того, как короткое `monolith:00020bddf721` на дев-сервере
приняли за другой образ. Без него не видно, что строка неполная. Полное имя:

```bash
docker ps --format '{{.Names}}\t{{.Image}}'
```

Тег на дев/проде — это SHA коммита (`$CI_REGISTRY_IMAGE:$CI_COMMIT_SHA` в
`.gitlab-ci.yml`), так что по нему восстанавливается сборка: `git show <тег>`.

Штатным `--format` так не сделать: у docker-шаблонов нет арифметики, чтобы взять
последний элемент `split`, — поэтому постобработка в `awk`. Интервальные
квантификаторы (`{32,}`) в регулярках намеренно не используются: их не все
версии `mawk` понимают, длина проверяется через `length()`.

```bash
dcps                        # все запущенные
dcps -a                     # вместе с остановленными
dcps --filter name=old-cms  # только нужный стек
```

Имя `dcps`, а не короткое `dc`: `dc` — это системный GNU-калькулятор в `/bin`,
и в интерактивном шелле Ильи он выигрывал по `PATH` у `~/.local/bin`. Команда
молча ждала ввода вместо таблицы — подробности в граблях.

**Почему не однострочник `docker ps --format`.** У `docker ps` нет поля с IP —
`.Networks` отдаёт только имена сетей. IP добирается отдельным `docker inspect`
на каждый контейнер. Контейнер может быть в нескольких сетях (типично для тех,
кто смотрит наружу через traefik) — тогда адреса перечислены через запятую.

## `dci`

```
IMAGE ID      REPOSITORY              TAG         SIZE    CREATED
0a8ba0e5c5ed  old-cms-monolith-local  php-8.1.27  920MB   10 minutes ago
810f35ef6f6d  old-cms-goevent-local   go-1.23.1   14.3MB  11 minutes ago
```

```bash
dci                          # все образы
dci 'old-cms*'               # по маске репозитория
dci --filter dangling=true   # только висячие
```

Здесь хватает штатного `--format`, поэтому скрипт — одна строка `exec`.

**Требуют на машине:** `docker`, а для `dcps` ещё `column` (util-linux), `paste`,
`tr`, `grep`. На Debian 11/12 всё есть из коробки.

## Установка

### Локально, без sudo (рекомендую)

`~/.local/bin` уже в `PATH`, причём раньше `/usr/local/bin` и `/usr/bin`:

```bash
for s in dcps dci; do install -m755 ~/.claude/skills/scripts/bin/$s ~/.local/bin/$s; done
```

### На сервер

**Только по явной команде Ильи — см. правило вверху.**

Пайпом, чтобы не спотыкаться о кавычки:

```bash
for s in dcps dci; do
  cat ~/.claude/skills/scripts/bin/$s |
    ssh <хост> "sudo tee /usr/local/bin/$s >/dev/null &&
                sudo chmod 755 /usr/local/bin/$s &&
                sudo chown root:root /usr/local/bin/$s"
done
```

Проверка, что доехало и работает в неинтерактивном режиме — там, где сломался
бы шелл-алиас:

```bash
ssh <хост> dcps
```

### Сверить, что нигде не разъехалось

```bash
diff <(ssh <хост> cat /usr/local/bin/dcps) ~/.claude/skills/scripts/bin/dcps
```

## Как добавлять новый скрипт

1. **Проверить, что имя свободно** — и в `PATH`, и в дотфайлах, и на серверах:
   ```bash
   command -v <имя>; grep -rn "alias <имя>=\|^<имя>()" ~/.bashrc ~/.bash_aliases
   ssh <хост> command -v <имя>
   ```
2. Положить в `bin/`, первой строкой `#!/bin/sh`, сверху — комментарий с
   примерами вызова.
3. Проверить синтаксис не запуская: `sh -n bin/<имя>`.
4. Дописать строку в «Инвентарь» — обязательно с колонкой «где стоит», иначе
   через месяц не найти все копии.
5. Разнести по местам установки и проверить на каждом.

## Грабли

- **Одноимённый алиас делает скрипт невидимым.** В интерактивном шелле алиас
  разворачивается раньше, чем ищется файл в `PATH`. Так и вышло с прежним именем
  `dps`: в `~/.bashrc` жил старый `alias dps="docker ps --format …"`, Илья видел
  его вывод, а установленный скрипт не запускался никогда. Коварство в том, что
  проверка из скрипта врёт: `command -v dps` в неинтерактивном шелле показывает
  файл, потому что `.bashrc` там не читается. **Проверять только в живом
  терминале**, а после удаления алиаса из `.bashrc` не забыть `unalias` — на уже
  открытый шелл правка файла не действует.
  (Алиасы `dps` и `dpsa` удалены 2026-09-07, бэкап `~/.bashrc.bak-*`; `dpsn`
  оставлен — он отдаёт голый список имён и нашими скриптами не покрыт.)
- **Короткое имя может перекрыть системную команду — и проверять надо в ЖИВОМ
  терминале.** Имя `dc` заняли, не подумав: `dc` — это GNU-калькулятор в `/bin`.
  Он молча читает stdin, поэтому команда выглядела как «ничего не выводит», без
  ошибки. Коварство в том, что у неинтерактивного шелла (в котором работает
  Claude) `~/.local/bin` стоит в `PATH` раньше `/bin`, а у интерактивного шелла
  Ильи — позже. То есть у Claude всё работало, а у Ильи нет. Диагностика —
  `type -a <имя>` в СВОЁМ терминале: он печатает всех кандидатов в порядке
  PATH, и первый выигрывает. Вывод: короткие двухбуквенные имена лучше не брать,
  а проверку делать не только через `command -v`.
- **У остановленного контейнера docker 29 печатает `invalid IP`.** В JSON поле
  пустое (`"IPAddress":""`), но шаблонизатор рендерит нулевой адрес как литерал
  `invalid IP` — и `dcps -a` показывал в колонке IP мусор `invalid,IP`. Отсюда
  правило: фильтровать не пустые строки, а всё, что не похоже на адрес —
  `grep -E '^[0-9a-fA-F.:]+$'`. Проверять такое надо именно на остановленном
  контейнере: `docker create --name t <образ>; dcps -a; docker rm t`.
- **Пустое поле схлопывает колонки.** Таб — это IFS-пробел, поэтому два таба
  подряд `read` считает одним разделителем, и всё правее уезжает на колонку
  влево. Именно так контейнер без портов (`alloy`) ломал колонку `IMAGE`, идущую
  после портов. Лечится заглушкой прямо в шаблоне докера:
  `{{if .Ports}}{{.Ports}}{{else}}-{{end}}`. То же самое для `column -t` —
  пустых ячеек быть не должно.
- **Шелл-алиасы не годятся для серверов.** При `ssh host cmd` bash стартует
  неинтерактивно, `.bashrc` не читает и алиасы не разворачивает. Поэтому наши
  утилиты — файлы в `PATH`, а не алиасы.
- **Копии живут своей жизнью.** Симлинк с exFAT-диска на машину не сделать, так
  что установка — всегда `cp`/`install`. Поправил в `bin/` — обойди места
  установки из инвентаря, иначе версии разъедутся. Сверяться через `diff` выше.
  При переименовании не забыть удалить старые файлы во всех точках установки.
- **Права на exFAT не хранятся**: в репозитории у всех файлов вид `755`
  независимо от `chmod`. Реальный бит выставляется при установке (`install -m755`).
- **Скрипты на сервере общие для всей машины.** На дев-сервере Olimp рядом живут
  чужие проекты — `dcps`/`dci` теперь есть и у них.
- **`~/.docker/config.json` тоже влияет на вывод.** Там у Ильи задан
  `psFormat` (три колонки) — на наши скрипты не действует, они передают
  `--format` явно, но объясняет, почему голый `docker ps` выглядит иначе. В том
  же файле лежат токены доступа к реестрам — не светить.
