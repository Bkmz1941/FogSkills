# Зонды-замеры (характеризующий замер поведения)

Готовые куски для Unity MCP `execute_code`. Кладутся в вызов как есть,
правок в коде игры не требуют — всё через рефлексию.

| Файл | Что меряет |
|---|---|
| `hover_probe.cs` | что возвращает `Interactor.Raycast` для каждого объекта сцены с четырёх ракурсов, в осмотре и вне его |
| `pose_probe.cs` | что возвращает `GridCursor.ComputeObjectPose` — поза, поворот и вердикт — по сетке точек для набора объектов |
| `sit_probe.cs` | «Сесть»: выдвигает стул, садится, клип по зоне рук, блок постановки, возврат (INVARIANTS 33) |
| `sit_snap_probe.cs` + `sit_snap_probe_end.cs` | «За стол» настоящим снапом (ComputeObjectPose с самим стулом) → Сесть → замер кистей над столешницей → встать, вернуть; второй файл через 2–3 с после первого |

## Протокол, без которого замер ничего не доказывает

1. `stop` → `refresh_unity(compile)` → `play` → замер «ДО» в файл.
2. Правка.
3. `stop` → `refresh_unity(compile)` → `play` → замер «ПОСЛЕ» в другой файл.
4. `diff` построчно. Пустой дифф = поведение не изменилось.

**Между прогонами сцену не трогать.** Если в это время кто-то играет —
предметы переезжают, и дифф показывает дрейф сцены, а не вашу правку
(поймано 30.08: 32 «расхождения», все до одного — переезд вещей).

## Грабли зондов

- **Мышь подменить нельзя**: `InputState.Change` на `Mouse.current.position`
  затирается реальным курсором на ближайшем `InputSystem.Update()`, и замер
  уходит в случайную точку экрана. Двигать надо КАМЕРУ: развернуть её так,
  чтобы луч через фактический курсор шёл в нужную точку —
  `Quaternion.FromToRotation(localDir, worldDir)`, см. код зондов.
- **Состояние сцены возвращать в `finally`**: позу игрока и камеры, статику
  вроде `Interactor.ExamineHost`, свои спавны. Зонд, упавший посреди цикла,
  однажды оставил игрока лететь в пустоту и час выглядел как «регрессия».
- После переноса игрока — `Physics.SyncTransforms()`, иначе физика отвечает
  по старой позиции.
- `Interactor.ExamineHost` с 30.08 — СВОЙСТВО, а не поле (правка ilya-1c):
  доставать через `GetProperty`, с запасным `GetField`. В зондах уже так.
- **Камера в пробе может встать ЗА СТЕНОЙ**, и тогда первым по лучу идёт
  кусок стены — наведение честно глохнет, а выглядит это как «правка не
  помогла» (поймано 30.08 на тарелке в навесном шкафу). Ракурс считать от
  объекта: сторона комнаты — противоположная той, к которой он прижат
  (`-(Quaternion.Euler(0, yaw, 0) * Vector3.forward)` у настенного). Первым
  делом при странном «НИЧЕГО» — распечатать порядок попаданий луча.
- Дверцы и ящики закрыты после входа в play: слоты за ними считаются
  закрытыми, и постановка внутрь честно невалидна. Открывать в самом зонде
  (`ClickPart` при выставленном `ExamineHost`) и мерить следующим вызовом —
  створки едут не мгновенно.


## invariants_play.py (2026-09-01)

Живые инварианты в play: предмет в закрытой секции не наводится, жидкости не
переполнены, нет невидимых объектов, у вложенного есть `Container`. Каждое
правило — уже пойманный баг, список в `tavern-regress/INVARIANTS.md`. Запуск: play + python3.

## level_roundtrip.py (2026-09-01)

«Сохранить → загрузить → сверить мир». Нашло две тихие потери: пропажу
вложенных предметов при загрузке (42 → 36, каждый раз разные) и то, что
положения тумблеров не сохранялись вовсе. Запускать после любой правки
сохранения, контейнеров или спавна.

## Дрейф между play-сессиями (2026-09-02, ночной рефакторинг)

`pose_probe` внутри одной play-сессии повторяется построчно, а между двумя
сессиями на ОДНОМ И ТОМ ЖЕ коде и уровне расходится на 1–2 записи: `home_stove`
в точках стыка кухонного кита переворачивается 0° ↔ 90° (стык между двумя
соседями решается по порядку, который меняется от загрузки к загрузке).
`hover_probe` между сессиями совпадает построчно. Правило чтения диффа после
перекомпиляции: расхождения только у кит-объектов в точках стыка с прежним
вердиктом «блок» — дрейф, не регрессия; любое другое расхождение — регрессия.
Проверка честности дрейфа — `git stash`, перекомпиляция, повторный замер на
снимке: если снимок сам расходится с собой, дифф не про правку.
Запуск замера: `python3 measure.py hover_probe.cs <файл>` (пишет строки в файл).
