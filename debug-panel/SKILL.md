# Debug Panel — инструкция для Claude

Локальная панель в `/home/ilya/Documents/Work/Olimp-CMS/debug-panel/`. Не в гите, с кодом/инфрой CMS не связана. Zero-dependency Node (только stdlib, SigV4 руками), никаких `npm install`.

**Главное:** Илья пользуется панелью через меня — я дёргаю API сам через `curl` и отвечаю результатом. Открывать браузер нужно только если Илья явно просит «открой панель».

## Проверка и запуск

1. Проверить, жива ли: `curl -s -m 3 http://127.0.0.1:8930/api/config`
2. Если не отвечает — запустить в фоне (Bash с `run_in_background: true`):
   `node /home/ilya/Documents/Work/Olimp-CMS/debug-panel/server.js`
3. Порт занят чем-то чужим → `PORT=<другой> node server.js` и дальше использовать этот порт.

Сервер слушает только `127.0.0.1:8930`. UI: `http://127.0.0.1:8930`.

## API (использовать напрямую)

- `GET /api/config` — `{bucket, endpoint, region}`; заодно health-check.
- `GET /api/list?prefix=<p>&token=<t>` — листинг с `delimiter=/`:
  `{prefixes: [...], objects: [{key, size, lastModified}], nextToken}`.
  Пагинация по 500 — если `nextToken != null`, продолжать с `token=`, НЕ отвечать по неполному листингу.
  `prefix` — навигация по «папкам» (`prefix=imports/`).
- `GET /api/presign?key=<key>` — `{url}`, presigned GET на 10 минут.
  Скачать файл для анализа: presign → `curl -o` в scratchpad (или `-r 0-N` для первых байт больших файлов).
- `POST /api/delete?key=<key>` — удалить объект. **Деструктивно и необратимо.** Перед вызовом
  подтвердить у Ильи конкретный ключ (или список ключей), если он не назвал файлы однозначно сам.
  S3 отвечает успехом и на несуществующий ключ — после удаления перепроверять листингом.

Типовые просьбы и что делать:
- «что там на S3 / что залилось» → list, свести в короткую таблицу (имя, размер, дата), даты в ответе — UTC.
- «скачай/покажи файл X» → presign → curl в scratchpad → показать содержимое/анализ.
- «дай ссылку» → presign, отдать URL (предупредить: живёт 10 минут).

## Конфиг и безопасность

- Креды в `~/.segmenter-s3.env` (`S3_URL`, `S3_BUCKET`, `S3_SERVERCORE_ACCESS_KEY_ID/SECRET_ACCESS_KEY`). **Никогда не выводить значения секретов** — при отладке маскировать: `sed -E 's/=.*/=***/'`.
- Env-переменные процесса имеют приоритет над файлом — так можно указать на другой бакет/endpoint не трогая файл.
- Из мутирующих операций есть только delete (см. выше). Write/upload-эндпоинтов нет — не добавлять без явной просьбы Ильи. Массовые удаления («почисти бакет», «удали все csv») — сначала показать полный список под удаление и дождаться подтверждения.

## Устройство и расширение

- `server.js` — весь бэкенд: загрузка env, SigV4 (`signedHeadersRequest`, `presignUrl`), запрос к S3 (`s3Request`), regex-парсинг XML листинга (`listObjects`), http-роутер внизу файла.
- `public/index.html` — весь UI одним файлом (тёмная тема, сайдбар слева).
- Новый инструмент = эндпоинт `/api/...` в роутере `server.js` + ссылка в сайдбаре + страница/секция в `index.html`. Держать стиль: zero-dep, stdlib, localhost-only, секреты не попадают в браузер.
- После правок перезапустить: убить старый процесс (`pkill -f 'debug-panel/server.js'`), поднять заново, проверить `curl /api/config`.

Илья просит «добавь в панель X» → это работа в этой папке, без оглядки на конвенции CMS-сервисов (это не сервис CMS).
