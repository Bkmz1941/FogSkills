# Регресс движка game-engine-rng

Скрипт — `probes/regress.ts` в репозитории. Гоняет **живой** движок по сокету
через настоящий api-core и поддельного оператора, проверяет и ответы протокола, и
строки в MySQL. 26 проверок, первый зелёный прогон — 2026-09-21.

Не путать с `npm test` — там юнит-тесты на чистые функции и конфиги, БД и сети
они не трогают.

## Стенд

Всё крутится локально у Ильи, движок и оператор — в сети api-core
(`crash-heroes-backend-api-core_minigames_net`), скрипт — на хосте.

```bash
# 1. api-core (MySQL mini_database, backend :8000) — первым, иначе сеть не найдётся
cd ~/Documents/Work/CrashGames/crash-heroes-backend-api-core
docker compose -f docker-compose.dev.yml up -d

# 2. поддельный оператор: ключи берёт из БД сам по PROJECT_ID, в аргументы секреты не попадают
cd ~/Documents/Work/CrashGames/game-engine-rng
docker rm -f fake-operator
docker run -d --name fake-operator \
  --network crash-heroes-backend-api-core_minigames_net \
  -p 127.0.0.1:4000:4000 \
  --env-file .env -e PROJECT_ID=2 -e PORT=4000 \
  -v "$PWD":/app:ro -w /app node:24-alpine \
  node src/resources/tests/support/fake-operator.ts

# 3. движок
docker compose up -d --build

# 4. прогон
REGRESS_DB_HOST=127.0.0.1 node --env-file=.env probes/regress.ts
```

**`-e PORT=4000` обязателен**: `--env-file .env` тащит `PORT=3100` от движка, и
без переопределения оператор поднимется на порту движка.

Переменные скрипта (все с умолчаниями): `REGRESS_API_CORE`,
`REGRESS_ENGINE_WS`, `REGRESS_OPERATOR`, `REGRESS_PROJECT_ID` (2 — «Local test
partner»), `REGRESS_STAKE` (1000 минорных), `REGRESS_SWEEP_WAIT` (75000 мс),
`REGRESS_DB_HOST` (перекрывает `DB_HOST` из `.env`: в контейнере это
`mini_database`, с хоста нужен `127.0.0.1`).

Прогон занимает ~2 минуты: почти всё время — ожидание чистки брошенных игр
(таймер раз в минуту) и лестницы ретраев роллбэка.

## Что проверяется

**Подключение**

- нет `?session=` → закрытие `4401 Session required`, перед закрытием приходит
  сообщение `{type:'error'}` с причиной;
- неизвестная сессия → `4401 Session not found`;
- путь не `/v1` → `4400 Unsupported protocol version` (до похода в БД).

**Протокол**

- `profile` → `balance` строкой и `currency`;
- `coefficients` (до 23.09 `get_coeffs`) → массив из 49 значений **прямо в `data`**, первый `1.0582`;
- `state` без игры → `data: null`, с игрой — вид игры прямо в `data` (до 23.09 `{game: …}`);
- у игры в ответе есть `balance` и **нет** `bet` (с 22.09 поле называется `round`);
- `start` отвечает сразу `rolling: true`, результат приходит отдельным событием
  `result` **с тем же `id`**, что и запрос;
- пока летит бросок, остальные команды игры → `Game is busy`;
- `cash_out` без активной игры → `No active game`.

**Деньги**

- выкупленная игра → у оператора ровно две операции: `bet` и `win`, обе
  `completed`;
- проигранный → только `bet`;
- оператор ответил 402 → игра `declined`, операция `bet` в статусе `canceled`,
  деньги не двигались;
- оператор ответил 503 → игра `not_confirmed`, `bet` остаётся `awaited`, движок
  **сам шлёт `rollback`**, и воркер ретраев дотягивает его до `completed`
  (поддельный оператор валит первые две попытки, роллбэк проходит с третьей).

**Протухшая сессия**

- сессии руками ставится `expires_at` в прошлое;
- чистка закрывает брошенную игру в пределах минуты;
- игра с выигранным раундом **выкупается**: статус `cashed_out`, проставлен
  `payout`, оператору ушёл `win`.

## Поддельный оператор

`src/resources/tests/support/fake-operator.ts`, в образ не попадает.

- **Ключи из БД.** С `PROJECT_ID` читает `projects.api_key`/`api_secret` сам
  (нужны `DB_*` из `.env`). Без `PROJECT_ID` берёт `API_KEY`/`SECRET` из
  окружения, как раньше.
- **Управление сценариями — `POST /control`** без подписи:
  `{"bet": 503}` — следующий вызов `/bet` вернёт 503, `{"win": 402}` — то же для
  `/win`. Срабатывает один раз и снимается; пустое тело сбрасывает всё.
  Появилось потому, что старые сценарии по префиксу `betId` (`decline-…`,
  `down-…`) больше не работают: движок кладёт в `betId` uuid игры.
- Идемпотентность по `txId` и флаки-роллбэк (первые две попытки 503) остались как
  были.

## Грабли

- **Баланс оператора живёт в памяти процесса.** Перезапустил контейнер —
  снова 100000, а зеркало в `player_wallets` осталось прежним; первый же
  `profile` их синхронизирует.
- **Игра может крахнуться на первом же раунде** (3/36), и тогда ветка проверок
  про выкуп не отработает — скрипт это учитывает и проверяет другую ветку, но
  случай «протухшая сессия» требует живой игры и честно пишет, что надо
  прогнать ещё раз.
- **Кости берутся из настоящего потока** `wss://dicestream.crash-heroes.com/ws/events`:
  без сети прогон встанет на `Dice unavailable`.
- Скрипт пишет в БД только одно — двигает `expires_at` своей же сессии.
