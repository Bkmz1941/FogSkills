## T-ACTOR — общее из стычки вороны под второго монстра (Илья 17.09: «запиши в туду для рефакторинга, я на ночь поставлю»)

Ворона и общее сшиты в одних классах: второй монстр не возьмёт решения, время,
камеру, урон, проверку и возврат, не утащив птицу. Цель ночи — разрезать по
четырём швам так, чтобы поведение вороны не изменилось ни на кадр. Это тот
случай, который проект назначил себе 11.09 («движок не строить, общую форму
вытащить на второй твари»): вторая тварь пришла, слой «впрок» по-прежнему не
делаем — режем ровно на размер двух актёров: по узлам (ворона) и по клипу
(гуманоид). Не смешивать с T-ARCH: переезд птиц из `Cozy.Grid` — не часть цели.

**Защита (crown_attack открыт, play, ворона на уровне):** `encounter_probe.py
rules` и `track` — детерминированы, diff посимвольно до и после КАЖДОГО шага;
`scenes` — цепочка, жизнь, ошеломление по всем развязкам; `check_all.py`,
EditMode-тесты, `night.py verify` (там же отпечаток дебаг-панели). В конце ночи
живой прогон: спереди — защита, уклонение, таймаут в удар, гибель при жизни ≤
урона удара; сзади — уклонение, таймаут в удар ничком, подъём с живота.

**Не трогать:** ключи `DebugTune` (`GuardEffect.Health`, `BraceTime.Slow`,
`Guard.CameraYaw`, `CrowAttack.*`, `CrowAttackRepeat.Seconds`…) — по ним лежат
числа Ильи; статики `Cozy.Combat.CrowEncounter.*`, `CrowAttack.StartAt /
CancelCurrent / Running / StartedAt / EndedAt`, `Encounter.*` — их зовут
`encounter_probe.py`, `EncounterBarUI.cs`, `HudUI.DebugMonsters.cs` (уходит фасад
— проба и панель правятся тем же шагом); формат `crowEncounter.json` — его
пишет `crow_fight.py` из Blender, только расширять; имена сцен
`brace/guard/dodge/hit/fall/back/backDodge/backHit`.
