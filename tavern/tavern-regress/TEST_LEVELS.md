## Принцип

- **Под домен — свой уровень** (`<домен>_test`, файл `~/.config/unity3d/DefaultCompany/Tavern/levels/<Имя> (test).json`). На нём только то, что нужно для кейсов домена: голый пол, столы-площадки, нужные приборы. Боевые уровни (level1 «Котедж 104» и др.) для регресса домена НЕ используются: на них слишком много всего, и результат не воспроизводится.
- **Кейс = код + стенд + шаги + ожидание.** Код `<ДОМ>-<группа><номер>` (`PT-A01`), стенд — что и где стоит на уровне (стол №, прибор), шаги — что делает игрок, ожидание — что должно получиться, измеримо. Кейс без ожидания — не кейс.
- **Воспроизводимость.** Стенд держится в самом уровне: нужное разложено по столам заранее и сохранено. Перед прогоном уровень загружается заново из файла (не из живого состояния прошлого прогона). Если кейс портит стенд (съел, разрезал, сжёг) — после прогона уровень перезагрузить, НЕ сохранять.
- **Защита.** Каждый кейс со временем получает автоматическую пробу в play (`probes/`): загрузить тестовый уровень, выполнить шаги кодом, сверить ожидание. Пока пробы нет — кейс прогоняется руками, в колонке «Защита» стоит ⏳.
- **Новая механика или продукт** — сначала кейс здесь, потом объект на стенд тестового уровня, потом проба. Грабля по домену (P-номер) — ссылка из кейса, который её ловит.
- Уровень правит только Илья (или сессия по его слову), стенд описан здесь — расхождение файла уровня с этим описанием = починить описание или стенд, сказать Илье.

## Как прогонять самому (Илья 18.10: «научись на этом уровне сам прогонять и проверять»)

1. `python3 probes/start.py` — мост, play. Уровень в редакторе — Ильи (`cycle.py play` уровень не меняет, инвариант 184); нужный тестовый уровень открывает Илья.
2. Код правил → `python3 probes/offline_build.py` (чисто) → в play код попадает только после перезахода: `cycle.py stop` (откажет при несохранённом у Ильи — тогда НЕ `--force`, а попросить сохранить/перезайти) → `cycle.py play`.
3. Пробы уровня (каждая создаёт свои объекты и удаляет их, чужое не трогает):
   - `products_probe.cs` — продукты (PT-A01, PT-A02, PT-C);
   - `padlock_hang_probe.cs` — замки (PT-L01…L05);
   - `doors_probe.cs` — двери, замки, ключи, дверцы (DR-…, кейсы `DOORS.md`, стенд `doors_test` ниже);
   запуск: `python3 ~/.claude/skills/tavern-game/mcp_call.py execute_code '{"action":"execute","code": <текст пробы>}'` или `python3 probes/measure.py <проба> /tmp/out.txt`.
4. Порядок при починке: проба КРАСНАЯ на старом коде (ловит баг Ильи) → правка → перезаход → ЗЕЛЁНАЯ → только тогда «готово» Илье. Скрин Ильи после «готово» = проба смотрит не туда — дописать проверку, а не крутить числа.
