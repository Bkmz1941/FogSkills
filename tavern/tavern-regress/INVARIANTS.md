# Инварианты: что обязано работать всегда

Илья, 2026-09-01: «это крит проблема, надо это описать в скиле, чтобы мы не
возвращались к тем проблемам, что уже решали».

Каждая строка — правило, которое обязано держаться всегда, и способ
проверить его за минуту. История самих багов (симптом → причина → решение)
живёт в `tavern-game/PITFALLS.md` записями `P…`; столбец «Грабли» ведёт
туда. Здесь только правила и защиты.

## Как этим пользоваться

1. Перед правкой — брифинг по области:
   `python3 ~/.claude/skills/tavern-regress/probes/bugs.py <область>`
   (инварианты области, правила из граблей, чем проверять). Области — те же,
   что у граблей: процесс, блендер, габариты, наведение, осмотр, части,
   контейнеры, постановка, перенос, жидкости, обводка, рендер, приборы, дефы,
   сейв, ui, готовка.
2. После правки — `probes/check_all.py`: линт, компиляция, тесты EditMode
   (60+), живые пробы `probes/invariants_play.py` и
   `level_roundtrip.py`.
3. Новый пойманный баг — запись в `PITFALLS.md`; если его правило обязано
   держаться всегда — строка сюда со ссылкой на P-номер. Проверку, которую
   можно автоматизировать, автоматизировать сразу: правило, которое
   проверяется только глазами, возвращается.

## Как добавлять строки (правило для всех сессий)

Дописывай в КОНЕЦ таблицы со следующим номером и не переставляй чужие строки:
файл общий, и три сессии за час уже успели вставить два дубля с одинаковыми
номерами. Если правило пересекается с существующим — не заводи новое, а
дополни старое: инвариант один, поводов сломать его много. Область — одна-две
из списка выше, первая главная. `bugs.py --lint` ловит дубли номеров,
неизвестные области и ссылки на несуществующие записи.

## Правила, которые эти инварианты охраняют

- **Одно место правды.** «Заперт в закрытой секции» — это `ContainerSlot.HoldsClosed`,
  и никакой путь не имеет права решать это сам. Каждый новый путь выбора цели
  обязан спросить его же.
- **Флаг родителя выводится из детей.** `ObjectDef.UsedAnywhere` = флаг дефа ИЛИ
  часть, объявившая глобальность. Иначе «чистка лишнего флага» убивает механику.
- **Механика без пути до неё мертва.** Есть тумблер — должен быть способ нажать.
- **Отложенный `Destroy`.** Уничтоженный в этом кадре объект ещё живой для
  `FindObjectsByType`: гасить перед удалением, иначе новая жизнь цепляется за
  труп (потеря предметов при загрузке уровня).
- **Новая механика без сохранения — половина механики.** Завёл новое состояние
  (связка, грязь, вкус, положение рычага) — в тот же день прогони
  `level_roundtrip`: сохранение молчит, когда состояние не пишется, и потеря
  всплывает у игрока через неделю.
- **Тест описывает не весь смысл поля.** Прежде чем «почистить» данные по
  красному тесту, грепнуть, кто это поле читает.
- **Носимое не участвует ни в чём.** Ни опора, ни препятствие, ни цель
  (`GridCursor.I.Carried`).
- **Правило наведения проверяется на паре случаев.** «Носитель ни в чём не
  лежит» и «носитель сам вложен»; «откуда виден предмет» — на четырёх (P044).
