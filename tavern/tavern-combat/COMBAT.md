## ⭐ КАК СЕЙЧАС — карта кода стычки (ночь 17→18.09, ilya-15; читать вместо разделов 14.09 ниже)

Разделы ниже — хронология с отменами: «Resolve», «Chance/Fail», «TailShare01»,

| данные | `EncounterData` (`EncounterData.cs`) | `crowEncounter.json`: сцены с клипом, кадрами, треком птицы `crow[]`, треком камеры, тазом на концах; верхний уровень — воронье (`headStab`, `tailFollow`, `beakOpen`, `crowSeam`) |

**Как завести второго монстра** (не сделано — ждёт решений в `OPEN.md`, «Второй
монстр в стычке»): свой `EncounterGraph` со своими сценами и префиксом ключей
дебага; свой актёр (гуманоид — второй Humanoid-клип через `CharacterAvatar`,
общий базовый тип с `CrowActor` заводится в этот момент); своя погоня, которая
на контакте зовёт `Encounter.Begin(граф, …)`. Что осталось приварено к вороне:
`SceneCam` и дефолты камеры (`CrowAttack.SceneDefault`) читают данные вороны;
`CrowAttack` держит и полёт, и общий контакт/моргание вместе (шов 4 цели
T-ACTOR — резать, когда появится вторая погоня).

**Чем защищено:** `encounter_probe.py rules` (таблица), `scenes` (цепочки,
жизнь, ошеломление), `track` (данные), `pose` (поза птицы по девяти сценам на
пяти долях + переходы brace→guard и back→backDodge), `night.py verify`
(компиляция, 158 тестов, живые пробы, отпечаток панели дебага).

тех же узлов вверх — локальная Z, продольная ось клюв-хвост — Y. **Поза,
перенесённая из сцены в игровой компонент один в один, встанет криво**: числа
те же, оси другие, проверять только замером в play.

### 1. Архитектура: птица → атака → стычка → граф

| Слой | Класс, файл | Отвечает за |
|---|---|---|
| птица | `CrowFlight` (`Cozy.Grid`) | живёт сама; `Hijack()`/`Release()` отдаёт себя стычке и возвращается на насест; `DivePose(dive, lift, twist, sweep, tailFan, legsDeg, headAim, beakDeg)` — поза узлов ПО СМЫСЛОВЫМ числам, разворот корня ставит вызывающий |
| атака | `CrowAttack` (`Cozy.Combat/CrowAttack.cs`) | ПОГОНЯ по радиусу контакта (как было) + ФАСАД ручек дебага (`CameraYaw…`, `CrowHeight`, `Wing*`, `SceneSeconds`, `SlowTailSeconds`, `DiveFlapHz`, `ContactRadius`, `ShowContact` — имена не менялись, `DebugTune` ключи те же, настройки Ильи живы). На контакте — `LookFade.Cut` и в черноте `Encounter.Begin(...)`. `StartScene1()` = `StartAt("brace")`, `StartAt(id)` стартует стычку сразу с любой сцены (кнопки «Старт: защита / уклонение») |
| стычка | `Encounter` (`Cozy.Combat/Encounter.cs`) | РАННЕР СЦЕН: постановочная рамка, клип, треки птицы и камеры, время (замедление, хвост, удержание), выбор, переход в следующую сцену, завершение (игрок остаётся на новой точке, птица отпускается). Статики для UI: `Running`, `Deciding` (идёт сцена с выбором), `Holding`, `SceneId`, `Choices`, `Remaining01`, `TailShare01`, `Choose(id)`, `ChooseSlot(slot)` |
| граф | `CrowEncounter` (`Cozy.Combat/CrowEncounter.cs`) | ЧТО ЗА ЧЕМ: `First = "brace"`, `ChoicesOf(scene)` → варианты (`EncounterChoice`: `Id`, `Slot` left/right/top, `Label`, `Next`, `Chance`, `Fail`), `Resolve(choice)` → id следующей сцены (при `Chance < 1` и заданном `Fail` бросок `Random.value`), **`TimeoutOf(scene)`** → сцена, которая идёт сама, когда таймер вышел без выбора (`brace` → `hit`, Илья 14.09). ### 2. Данные из Blender — `crowEncounter.json`, один файл на все сцены

Пишет `export_scene(...)` в `crow_fight.py` (14.09) — каждая сборка
(`anim_kit.py build Crow_Brace | Crow_Guard | Crow_Dodge`) переписывает ТОЛЬКО
свою запись в `scenes`, остальные не трогает; верхний уровень (`playerHeight`,
`headCenter`, `crowSeam`, `headStab`, `tailFollow`, `tailFan`, `legTuck`,
`beakOpen`) одинаков у всех и переписывается каждой. Старый `crowAttack.json`
снесён. FBX клипов: `Crow_Brace.fbx` (24 кадра), `Crow_Guard.fbx`,
`Crow_Dodge.fbx` (по 132) — меты скопированы с `Crow_Brace.fbx.meta` (Humanoid,
`loopBlendPositionXZ 1` = сдвиг таза ВПЕЧЁН в позу, корень не едет).

- **Оси:** всё в локальных осях ИГРОКА от ПОЛА под ним: `(right, up, forward)
  = (−x, z, −y)` Blender. Курс птицы `yaw` в игре = **минус** блендеровский
  (в Blender 180° = лицом на человека).
- **Ключ птицы** (`CrowKey`): `frame`, `pos`, `dive` (+ носом вниз), `roll`
  — и `tail` (тангаж хвоста, °; с 14.09 игра НЕ считает хвост сама:
  `DivePose` берёт градусы из трека). В Blender `tail = max(−6, TAIL_FAN −
  TAIL_FOLLOW·dive)`: ось хвоста у модели ВНУТРИ корпуса, и ниже −6° веер
  уходит в тело (замер BVH по `Crow_Hit`: в пике −18° → 58 % вершин хвоста
  внутри, при −3° — 33 %, это норма модели; при +5…+25° на взлёте снова
  58 %, выше +35° — 0 %). Илья 14.09: «хвост пропадает текстурами». Проба —
  `scratchpad/tail_probe.py` (BVH «внутри/снаружи» по кадрам) —
  (+ правое крыло вверх, знаки сверены аналитически: Blender `YXZ` ≡ Unity
  `Euler(dive, yaw, roll)`), `yaw`, `flap`/`twist`/`sweep` (числа
  `spread_wings`/`wing_beat` ДО знака стороны), `legs` (градусы узла `Legs`:
  34.1 = поджаты, −18 = пошли вперёд на стыке, −52 = выброшены в ударе),
  `headAim` (доворот головы в цель поверх гашения `HEAD_STAB`), `beak` (доля
  хода 0..1; в игре × `beakOpen` 72°). Ключи только там, где в Blender стоял
  `key_crow` (защита и уклонение — 96 ключей на 132 кадра, уход через кадр).
- **Ключ камеры** (`CameraKey`): `frame`, `pos`, `look` (= pos + взгляд),
  `lens`. Снимается с камеры Blender ПО КАДРАМ (`scene.frame_set`), поэтому
  переезд `travel_cam` и доезд за человеком в уклонении едут в игру как есть.
  У статичной камеры «замера» — один ключ.
- **`stage`** только у сцены 1: `crowOffset`, `crowFar`, `crowDive`,
  `crowBeak`, `cameraLook`, `cameraOffset`, `cameraLens`, `wingsDive` — из них
  считаются дефолты ползунков и геометрия погони (как раньше из
  `crowAttack.json`). `SceneData.Tunable` = есть `stage` — такую сцену
  крутят ползунки, остальные играются по трекам.
- **Запись трека:** `spread_wings`/`wing_beat` кладут тройку крыла в `_WING`,
  `dive_pose` — тело в `_BODY`, `key_crow(root, frame)` складывает
  `TRACK[frame]`. Новая сцена получает трек бесплатно, если ставит птицу теми
  же функциями.

### 3. Как раннер играет сцену — контракт

1. **Рамка** (`_framePos`, `_frameRot`) снимается ОДИН РАЗ на старте стычки
   (в черноте моргания): игрок довёрнут под угол захода (`side` из
   `stage.crowOffset`, как 13.09), рамка = стопы игрока (`FeetOf`, корень на
   метр выше — P-запись 13.09) + его yaw. Все ключи всех сцен считаются от неё:
   `ToWorld(local) = _framePos + _frameRot · local`. Корень игрока в сценах не
   двигается — ходит ТЕЛО внутри клипа.
2. **Старт сцены** (`StartScene`): `Choices = CrowEncounter.ChoicesOf(id)`,
   таймер `_t` (игровое время) и `_realT` в ноль, клип на `CharacterAvatar.
   PlayPreview` (стык: последний кадр прежнего = первый нового, сверено
   `crow_seamdiff`: 0.00000 м птица, 0.00000 поза, 0.0072° камера), FOV из
   `lens` первого ключа камеры, время: сцена с выбором —
   `Seconds / SceneSeconds`, без выбора — обычное.
   ⚠️ **Длина сцены `Seconds = (frames − 1) / fps`** (0.958 с у замера), а не
   `frames / fps`: последний ключ трека — кадр 24 = 23/24 с, и лишние 0.04 с
   игрового времени при масштабе 0.08 давали ПОЛСЕКУНДЫ реального стояния
   птицы у стыка (Илья 14.09: «ворона замирает в конце, смысл — чтобы всегда
   было движение, только замедленное»). Теперь переход ровно в момент, когда
   птица дошла до стыка.
   ⚠️ **Время клипа ставится КАЖДЫЙ КАДР** — `CharacterAvatar.PreviewSeek(_t)`

   на `timeScale` не смотрит, шаг назад проигрывался за первую реальную
   секунду. Теперь клип человека, трек птицы и камера — один такт `_t`; в
   удержании `_t = Seconds`, клип стоит на последнем кадре; на переходе
   `_t = 0` — ровно первый кадр следующей сцены.
3. **Каждый кадр** (`Drive`): `frame = 1 + _t·fps`; птица = `CrowAt(frame)` +
   `CrowHeight − stage.crowOffset.up` по вертикали — в сцене 1 целиком, в
   развязках ТОЛЬКО на стыке, с затуханием за 1 с (`HeightBlendSeconds`):
   ⚠️ тюнинг Ильи −0.18 сажал птицу в голову во всех развязках («нельзя

   ползунки + процедурный мах `35°·sin(2π·DiveFlapHz·t)` (числа Ильи), у
   остальных — трек, с ПОДМЕШИВАНИЕМ от текущих углов за 0.25 с

   подмешивания крыло дёрнется на первом кадре развязки; карканье — два
   импульса на старте сцены 1 (как 13.09); `DivePose(...)`.
4. **Камера:** `Tunable` — параметрическая от ползунков (`CrowAttack.
   CameraPose`), как 13.09; остальные — трек с ДЕЛЬТА-ПОДМЕШИВАНИЕМ:
   `pos = track(t) + (камера на старте сцены − track(1))·(1 − smooth(u))`,
   `u = (frame − 1) / cameraBlendFrames` (32 = подлёт + 8, число из
   `travel_cam`). Смысл: развязка начинается РОВНО с той камеры, что была
   (в том числе с накрученной ползунками), а к концу переезда стоит ровно
   по Blender; если камера сцены 1 совпадает с Blender — траектория
   совпадает с Blender посимвольно. Простой `Lerp(from, track(t), u)` дал
   бы кривую «квадрат сглаживания» и медленный старт — поэтому дельта.
   **Камера — ОДНА МОДЕЛЬ для всех сцен, цель — ГОЛОВА** (Илья 14.09: «цель,
   за которой камера следит, — голова персонажа»; «странно, что при одних
   и тех же настройках в разных сценах камера по-разному стоит»):
   `CrowAttack.CameraPose(sceneId, player, head, …)` — сферические
   координаты (поворот, наклон, дистанция) вокруг живой кости головы
   (`HeadOf`: `HumanBodyBones.Head` + 0.1 вверх) в осях игрока + сдвиг
   X/Y/Z точки взгляда. Одни числа → одна камера в любой сцене; камера
   ЕДЕТ за головой (упал — кадр опустился). Значения по сцене абсолютные:
   сцена 1 — статики `CrowAttack.CameraYaw/Pitch/Distance/X/Y/Z`,
   развязки — `CrowAttack.Guard/Dodge/Hit` с теми же именами; ДЕФОЛТЫ
   считаются из камеры Blender (`SceneDefault`: отступ камеры от точки
   взгляда на кадре `cameraBlendFrames + 1`); если в `DebugTune` лежит
   дистанция < 0.5 (старые нули-поправки), берётся дефолт. Треки камеры
   из Blender в игре больше не играются, только их первый кадр как
   дефолт. Переезд между сценами — дельта-подмешивание от камеры прошлой
   сцены за `cameraBlendFrames`, как раньше.
   **Прямой старт развязки** («Старт: защита/уклонение/успешная атака», Илья
   14.09: «экран тухнет и появляется камера на старте сцены, где
   установлена»; «сцена 4 камеру двигает, с 1 ок»): в `StartScene(scene,
   fresh: true)` точка «откуда» = поза трека на кадре `cameraBlendFrames + 1`,
   и на время переезда камера СТОИТ ровно в кадре сцены (трек и дельта
   взаимно гасятся: `track(1) + Δ·s + Δ·(1 − s) = track(33)`), переезда от
   камеры сцены 1 нет — её и не было в кадре. **После переезда камера
   развязки СТОИТ** (Илья 14.09: «камера в сцене, когда уже идёт, не надо
   чтобы двигалась после настройки»): трек камеры читается не дальше кадра
   `cameraBlendFrames + 1`, доезды камеры Blender внутри сцены (уклонение с
   кадра 36, спуск к сидящему в сцене 4 с кадра 44) в игре НЕ играются —
   кадр развязки один, его и крутят ползунки. В Blender эти ключи остались
   для просмотра.
5. **Время сцены с выбором:** один ход `Seconds/SceneSeconds` на всю сцену
   (Илья 14.09: «убери фишку сильного замедления — совсем»: хвоста 0.08,

   есть `TimeoutOf` (у `brace` — `hit`), она стартует САМА; иначе
   **удержание** `0.05` (`HoldTimeScale`) до выбора. Полоса: `Remaining01 =
   1 − realT / SceneSeconds`, цвета по порогам 70 % / 30 %.
   **Пауза** (Илья 14.09: «кнопку "Пауза", чтобы я мог поставить на паузу»):
   `Encounter.TogglePause()` — `timeScale` 0, такт `_t` и `_realT` стоят,
   `Drive()` продолжает каждый кадр, так что ползунки камеры и крыльев
   крутятся на замершем кадре; «Продолжить» возвращает масштаб сцены
   (`_sceneScale`: замер `Seconds/SceneSeconds`, развязка `Tempo`, удержание
   0.05). Кнопка в блоке каждой сцены, подпись меняется «Пауза» ↔
   «Продолжить». Отбой и конец сцены снимают паузу вместе со временем.
6. **Выбор:** `Encounter.Choose(id)` / `ChooseSlot(left|right|top)`;
   ✅ **только МЫШЬЮ по кнопкам** (Илья 15.09: «в сценарии 1 когда мы
   принимаем решение — убери нажатия на клавиатуру, только мышкой по
   кнопкам»). Горячие клавиши ← A / → D / ↑ W сняты вместе с

   кнопки дебага «Выбор: защититься / ускользнуть». Выбор В УДЕРЖАНИИ → следующая сцена сразу.
   Выбор РАНЬШЕ (пока замер идёт) → решение принято: замедление и хвост
   снимаются (`timeScale` обычный), сцена доигрывает до стыка и переходит —
   без удержания. 💡 Это допущение сессии, см. OPEN.md.
7. **Переход:** `Resolve(choice)` → `Scene(next)` → `StartScene`. Нет такой
   сцены — `Finish`.
8. **Конец** (`Finish` → `Cancel`): `SettlePlayer` — корень игрока переносится
   на XZ таза клипа, разворот — по линии бёдер (`Cross(бедроR − бедроL, up)`;

   грудью на −13° игрок разворачивался на 13°), затем `Physics.SyncTransforms()`

   назад (`m_AutoSyncTransforms 0`; P394). Потом время, камера
   (`EndCinematic`), FOV, `Veiled`, `StopPreview`, `onDone` → `CrowAttack.Done`
   → `Release()` птицы или уничтожение временной. Esc в любой момент —
   отбой тем же путём.

| 3 `dodge` (уклонение) | 0 | 40 |
| 4 `hit` (успешная атака) | 30 | 0 |

| | |
|---|---|
| где числа | `CrowEncounter.cs`: `BraceEffect` / `GuardEffect` / `DodgeEffect` / `HitEffect`, у каждого `Health`, `Energy` и два тумблера показа; свой снимок отдаёт `Snapshot`. ### Как это читать в коде (после рефакторинга 15.09)

Разбор id сцены живёт в ДВУХ местах, и больше нигде:

| нужно | зовут |
|---|---|
| числа и тумблеры сцены | `CrowEncounter.EffectOf(scene)` → снимок `SceneEffect` |
| тип холдера для панели дебага | `CrowEncounter.TuneOf(scene)` |

⚠️ **Новая сцена = новый холдер + две строки.** Завёл `FallEffect` — добавь

## ✅ ДВА МОМЕНТА АТАКИ И АТАКА ПО ИНТЕРВАЛУ (Илья 15.09)

Илья: «добавь кнопку в Ворону атака по интервалу вкл выкл и ползунок в секундах

2 3 4 5 сцен».

**Моменты — две отметки времени у `CrowAttack`** (`Time.unscaledTime`, публичные

| момент | где ставится | что это |
|---|---|---|
| `StartedAt` | `HandOff`, прямо перед `Encounter.Begin` | пошла ПЕРВАЯ сцена: при погоне — сцена 1, при отладочном «Старт: защита» — та, с которой стартовали |

отметка переживает уничтожение объекта атаки, событие — нет. Новая сцена
попадает в «конец атаки» даром: раннер зовёт `Done` сам, чем бы стычка ни
кончилась.

«включён ли», `Seconds` — интервал. Правило отсчёта: пока `CrowAttack.Running`
ИЛИ `PlayerPosture.Veiled` — счёт не идёт вообще, поэтому интервал меряется
ровно от `EndedAt`, длинная сцена паузу не съедает, а лежачего (сидит после
удара, встаёт) не бьют. Первая атака после включения идёт сразу.

if (Killed(_crow)) _crow.FallDead();
else if (_dummy) Destroy(_crow.gameObject);
else if (flewAway) _crow.ReleaseFlying();
else _crow.Release();
