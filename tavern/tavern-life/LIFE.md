стрелки — вся строка действия; без условий — один раз при загрузке (`on

(уникальность на уровне проверяется); словарь `[objects]` перечисляет виды с
номерами, `[named]` — явные имена.

Когда срабатывает: `[every 15 min]` и правила только с «none/has» — через 5 с
после загрузки и на каждой четверти игрового часа; `[HH:MM]` — при переходе часов

возврат), `CrowZoneSpawn.Place/RemoveCreature`. Всё — в «Действия монстров»

«События чувств — модели» (выкл), «Часовой тик» (модели; при пустых блоках

⭐ Осмотр по сторонам — два шага (Илья 10.10), код `CreaturePlan.Nav.cs`:
- `[look around left3s right 1s]` — НА ХОДУ, параллельно, как эмоция (шаг
  `Glance`): влево/вперёд/вправо/пауза (вперёд = пауза: голова прямо по ходу;
  Илья 10.10 «слева вперед вправо»), голова от текущего направления тела, ход
  сразу следующему шагу. С направлениями — один проход по их секундам;
  `[look around][10s]` — по кругу 10 с; `[look around]` — влево, вперёд,
  вправо, вперёд по кругу до конца реакции. Назад здесь — красная строка.
- `[look around/wait left3s back4s forward]` — СТОЯ, держит существо (шаг
  `Watch`, `mode = "around …"`): стоит, пока осматривается; все направления от
  того, куда смотрел В НАЧАЛЕ шага: влево/вправо — голова, назад — тело на
  180°, вперёд — тело в исходное. Без направлений — вправо, влево, назад,
  вперёд; в реакции на sees/hears без времени — пока видит/слышит.
- `pause3s` — пауза в списке: голова прямо 3 с (стоя тело не крутится);
  `loop` — список по кругу: на ходу/в реакции — до конца плана или `[Ns]`,
  без `loop` — один проход.
- В СТРОКЕ С `[go]`: `1. [go][zone/marker_2][walk][look around left2s right2s pause3s loop]`
  — осмотр часть хода (`mode = "glance …"` у шага `Go`), крутится пока идёт,
  ДОШЁЛ — прерывается (`_glanceWhileGo`, снимает `ResetStep`). Без `loop` —
  один проход за ходьбу. Отдельной строкой — свой шаг со своими секундами.
- Синонимы: влево/налево, вправо/направо, назад, вперёд/прямо/forward, пауза; цикл/по кругу;

⭐ Погоня и память места (Илья 10.10):
- `[go][player]` — идёт к герою, путь перестраивается каждые 0,4 с, у героя
  (1,2 м) стоит лицом к нему. Всю погоню голова смотрит на героя (`SetLook`
  в `BeginGo`; осмотр на ходу её не перебивает). В реакции на `[sees player]` реакция привязана к

- Память: `CreatureSenses.LastSeen` — где существо последний раз ВИДЕЛО героя,
  обновляется каждый кадр, пока видит; живёт `LastSeenSeconds` после потери
  (у сектанта 60 с, F1 → Монстры → Сектант → Чувства, «Помнит, где видел

- `[go][last seen]` (`last_seen`, `player last seen`, `где видел`,
  `последнее место`) — идёт туда; памяти нет — шаг пропускается; ДОШЁЛ —
  память стёрта.

### Что уходит модели (порядок = порядок во вкладке «ИИ»)

1. `[команды]` — системный текст пульта (`AiConsole.CommandsText`): форматы `spawn`,
   `remove`, `plan`, `say`, правила (один JSON или массив; target — слаг;
   на событие — короткий план без appear; ничего сверх описания; reply без
   результата).
2. `[сюжетное]`, `[триггеры]`, `[события]`, `[монстры]` — тексты Ильи из
   файла уровня (`LevelIO.Ai*`), редактируются во вкладке, у каждого «~N ток.».
3. `[снимок уровня]` — время и часть суток, игрок в доме/снаружи, зоны существ
   (слаг — имя — описание — размер, деревья есть/нет — кто там: **счёт по
   видам** «вороны: 2 (crow_2, crow_6)» — маркеры «1 — пол (x, z)»), существа
   (имя — вид — зона — маркер рядом — план `CreaturePlan.Describe`).
4. `[диалог]` — последние 8 строк (у тика/события — из журнала действий, у
   чата — из чата).
5. user: тик — «Прошёл час, HH:MM. Сначала сверь каждое правило из [событий] и
   [монстров] со снимком… делай только то, что ещё не сделано… Если нечего —
   say»; событие — «Событие: … Реши для who по его описанию в [монстры].
   Один короткий plan, remove или say».

Константы: `AiChatTemperature 0.1`, `AiChatTokens 220` (чат), `AiEventTokens
400` (тик/событие — планы длиннее), `AiTriggerGap 10 с` (антидребезг событий
на существо, последнее событие копится, не теряется), `AiMemoryLines 8`.
Контекст сервера 16K/1 слот (`LlmHost`), стабильный префикс кэшируется.

### Команды пульта → игра

- `spawn {{kind, zone, branch tree|ground|any, mark}}` → `CrowZoneSpawn.Place`
  (any → ветка с откатом на землю, явный tree без отката); отказ объясняется
  `CrowZoneSpawn.FailureText` («в зоне нет насестов», «нет земли —
  клетки на полу дома или заняты», «имя занято»).
- `remove {{kind|all, zone|all, who, mark}}` → `CrowZoneSpawn.RemoveCreature`
  (птицы — `Remove`, сектант — `Destroy`, `Unsaved` чистится внутри); маркер
  фильтрует по 3 м от клетки (`CrowZoneSpawn.AtMark`).
- `plan {{who, steps[], loop}}` → `CreaturePlan.Run`. Шаги: `appear {{zone,
  mark}}` (несуществующий who — сектант в маркер; существующий — пропуск),
  `go {{zone, mark | target, run}}`, `wait {{seconds}}`, `watch {{target|mark|герой,
  seconds}}`, `roam {{seconds}}`, `toggle {{target, mode on|off|flip}}`, `door {{mode
  open|close}}`, `vanish {{mode now|unseen}}`, `stop`. toggle/door сами подходят
  к объекту; target — слаг или название без кавычек. Зона плана = первая
  зона в шагах, иначе зона существа на момент плана; «go маркер N» без зоны —
  оттуда. Стек ≤ 2: план по событию поверх маршрута, по окончании —
  возврат на тот же шаг; событие заменяет прошлое событие.
- `say {{reply}}` — ничего не делать.

### Предохранители предсказуемости (кодом, не промптом)

- Тик при пустых [события]/[триггеры]/[монстры] модель не спрашивает (P990).
- План по тику или событию принимается только для существа, описанного в
  [монстры]; по чату оператора — для любого (P990).
- Существо без описания событий не шлёт (`CreaturePlan.Emit`).
- Провал шага — в логи, не в модель (P987). Стек планов ≤ 2.

### Чувства → события (`CreaturePlan.Sense/ScanObjects`, не чаще раза в 2 с)

«увидел героя в N м, герой у «Имя» (slug)» (существо само замирает лицом к
герою на 3 с), «потерял героя из виду», «услышал героя в N м, не видит»,
«видит «Имя» (slug, включён) в N м» — только объекты, названные в описании
существа (`Mentioned`: название, слаг или последнее слово названия ≥ 6
букв), раз в минуту на объект; «закончил план, у маркера N»; «прошло N с:
шаг 2/5 идёт к маркеру 3; не смог: …» раз в `Sectant.ThinkSeconds` (30 по
умолчанию, 0 — выкл). Провалы шагов — `GameEvents` «ИИ-план: …», не модели.

## 1. Что есть сейчас и где жмёт

Сегодня жизнь существа собирается из ТРЁХ несвязанных блоков в карточке зоны:

| Блок | Что хранит | Как связан с другими |
|---|---|---|
| **Маркеры** | номерные точки зоны (пол; у Тени — стены) | только номером |
| **События** | шаблон («Появление монстра», «Исчезновение вороны», «Атака», СМС…) + триггер + условия + поле «маркер» | «кого» — системным именем `who` |
| **Перемещения** | маршрут: `who` + шаги «идти к маркеру (зоны слаг) шагом/бегом», «стоять N с», повтор | с событием — только совпадением `who` |

Где жмёт (Илья 07.10: «меня смущает сейчас система зон и маркеров»):

- появление — в одном блоке, маршрут — в другом, а «ушёл» не существует;
  чтобы собрать одного сектанта, нужно три места и одно имя без опечаток;
- на точке нечего делать, кроме «стоять N с»: ни сесть, ни посмотреть, ни
  включить лампу, ни выбить дверь;
- свободное движение есть только у птиц (зона = где летает), у сектанта
  только маршрут;
- маркер — немой: по нему нельзя кликнуть и увидеть, кто и зачем его ждёт;
- реакции на игрока у сектанта нет вовсе, у вороны — две галочки.

Что хорошо и сохраняется: триггеры и условия событий (богатые, проверенные),
кисть зон и слои, маркеры на полу и стенах, пути по клеткам (`MonsterNav`),
свободный полёт вороны внутри зоны, системные имена существ.

## 2. Целевая модель — «Сценарий»

**Сценарий** — одна запись «как живёт один актёр»: кто, когда начинается,
где появляется, что делает по шагам, как уходит, как реагирует на игрока.
Технически это СОБЫТИЕ ЗОНЫ нового шаблона «Сценарий» (группа «Жизнь»),
поэтому триггеры и условия у него те же, что у всех событий.

```
Сценарий «Сектант у окна»              (зона: sectant_zone_1)
├─ Актёр:      сектант · имя sectant_1 (само: <вид>_<N>)
├─ Старт:      каждый вход игрока в зону · условия: ночь 22–6, свет выключен
├─ Появление:  маркер 2 (или: «где игрок не видит», «за кадром») · лицом к маркеру 3
├─ Шаги (по порядку, повтор: один раз / по кругу / туда-обратно)
│   1. идти к маркеру 3 шагом     → стоять 8 с; смотреть в окно window_kitchen
│   2. идти к маркеру 5 крадучись → выключить lamp_hall; стоять 3 с
│   3. бродить по зоне 40 с                      (свободное движение, как ворона)
│   4. идти к двери door_back бегом → выбить дверь
├─ Уход:       на последнем шаге исчезнуть, когда игрок не видит
└─ Реакции:    увидел игрока → замереть и смотреть 4 с, потом продолжить
               услышал игрока → повернуть голову (Ф3)
```

Части:

- **Актёр** — вид (`сектант` / `ворона` / `сова` / `зарянка`; потом люди) и
  системное имя. Имя даётся само (`sectant_1`), правится руками, как сейчас у
  «Появления монстра». Актёр задаёт, какие действия доступны (§4).
- **Старт** — триггер и условия события как есть. Дополнительно «Повтор
  сценария» (один раз / каждый старт / по интервалу — это и есть сегодняшний
  интервальный «респавн»).
- **Появление** — где возникает: маркер N (своей зоны или зоны того же типа
  по слагу — как в маршрутах), «ближайший к игроку, но вне кадра», «за
  кадром» (как сейчас у ворон). Поля вида: у птиц «на ветке / на земле»,
  «Активна», «Охотится» — переезжают сюда без изменений.
- **Действия** — плоский упорядоченный список, одно действие = одна вещь
  (Илья 07.10: «не добавить шаг — а добавить действие, и это список должен
  получаться — где действие и оно раскрывается»): «Дойти до маркера N»
  (шагом/бегом), «Дойти до случайного места зоны», «Подойти к объекту»,
  «Стоять N с», «Бродить по зоне N с», «Включить / выключить», «Открыть /
  закрыть дверь», «Исчезнуть». В редакторе каждое действие — строка-заголовок
  со сводкой, которая раскрывается в поля (как подблоки дебаг-панели), со
  стрелками порядка и корзиной.
  Повтор списка действий: один раз / по кругу / туда-обратно.
  ⭐ **Вариативность** (Илья 07.10: «нужна вариативность решений, чтобы была
  генерация поведения в разных ситуациях»): у шага есть «Условие» (`when`,
  те же условия, что у событий: шаг выполняется, если условие держится —
  иначе пропускается), «Вероятность» (`chance`, 0–100 %: шаг случайно
  выполняется или нет) и «Если не вышло» (`onFail`: пропустить / подождать N с
  и повторить / перейти к шагу K / закончить сценарий; «не вышло» — путь
  закрыт, объекта нет, маркер исчез). Так один плоский список даёт разное
  поведение в разных ситуациях без графа.
- **Уход** — что в конце: *исчезнуть сразу* / *исчезнуть, когда игрок не
  видит* (конус игрока и камера — честный хоррор) / *идти к маркеру N и
  исчезнуть* / *остаться* (бродить по зоне) / *остаться на месте*.
- **Реакции** (Ф3) — что делать, когда `CreatureSenses` говорит «вижу» /
  «слышу» игрока: игнорировать / замереть и смотреть N с / идти к игроку /
  бежать прочь к маркеру N / атаковать (когда будет бой) / после — продолжить
  шаг или начать заново. Реакция — тоже из каталога.

Птицы: их сегодняшняя жизнь = сценарий «появиться (ветка, активна) → бродить
по зоне бесконечно», маршрут вороны = шаги «перелететь к маркеру N, сидеть
N с» по кругу. Ничего не теряется, редактор один.

  зоне», условия, площадь для «бродить» и для появления «где не видно».
- **Маркер** остаётся точкой с номером (пол / стена), но получает РОЛИ по
  тому, кто на него ссылается: появление (фиолетовый, как старые маркеры
  респавна), шаг (красный), уход (тёмный), несколько — кольца. Роли не
  хранятся: считаются от сценариев.
- **Клик по маркеру** (в стройке, вне режима «Маркеры») ВЫБИРАЕТ МАРКЕР: панель
  выделения справа показывает «Маркер N · зона», корзина удаляет маркер, а
  «Редактировать» открывает ОКНО МАРКЕРА (`HudUI.OpenZoneMarkEditor`) — тот же
  блок «События», что в карточке зоны (`ZoneEventsSection(content, zone,
  mark)`): группа → шаблон → «Добавить событие», карточки только тех событий,
  что ссылаются на маркер; новое событие сразу привязано к маркеру
  (`LifeBindMark`: `mark`, у сценария — появление здесь, имя само), у сценария
  с появлением здесь поля «Где/Маркер» скрыты. Внизу «Сохранить»/«Отмена» с
  предупреждением — 1:1 как у зоны (Илья 07.10: «сделаем 1 в 1 как в
  редактировать зону, то есть флоу 1 в 1»). Клик по зоне мимо
  маркера — карточка зоны со всеми сценариями. Всплывающего попапа по клику
  НЕТ (Илья 07.10: «убери этот попап новый — давай только редактирование
  оставим», потом «надо чтобы маркер выбирался и настройки для него свои»,
  «ну редактировать справа»). Технически `UpdateZonePick` знает точку на
  плоскости зоны, `MarkNear` даёт номер → `Selection.zoneMark` →
  `HudUI._selectedMark` → `OpenZoneEditor` ветвится на окно маркера.
- **Режим «Маркеры»** (ставить/снимать кликом) — без изменений.

## 4. Каталог действий

Записи реестра `LifeActions`: ключ, подпись, поля, кто умеет, реализация,
этап. «Умеет» — по актёру (ходячий / летающий / человек), редактор
показывает только доступное.

| Ключ | Действие | Поля | Кто | Реализация | Этап |
|---|---|---|---|---|---|
| `wait` | стоять N с | секунды | все | стоит, клип покоя | Ф1 |
| `roam` | бродить по зоне N с (0 = пока не прервут) | зона (слаг, пусто = своя), секунды, пауза между точками | все | случайные достижимые клетки внутри формы зоны (`ZoneShape.Contains` + `MonsterNav`), у птиц — сегодняшний `PickTarget` | Ф1 |
| `toggle` | включить / выключить объект | слаг, вкл/выкл/переключить | ходячие, люди | лампа/выключатель (`WallSwitch`), телевизор, камин (`FireplaceFire.SetLit`) — через атрибут объекта «включается» | Ф1 |
| `door` | открыть / закрыть дверь или окно | слаг, открыть/закрыть | ходячие, люди | `DoorPiece.Toggle` / `WindowPiece.Toggle` (есть) | Ф1 |
| `vanish` | исчезнуть | сразу / когда игрок не видит | все | снять объект, как «Исчезновение вороны»; «не видит» — вне кадра и вне конуса игрока | Ф1 |
| `sit` | сесть на объект N с | слаг (`sittable`), секунды | ходячие, люди | посадка по узлу сиденья и клипу `sitClip` (есть у героя: стул, диван, кресло-качалка, скамейка); «за стол» = стул, у которого перед сиденьем столешница | Ф2 |
| `look` | смотреть N с | цель: окно (слаг) / игрок / объект / по сторонам, секунды | все | поворот головы (у сектанта — та же кость, что у чувств), у птиц — ручка взгляда (`CrowIdle`) | Ф2 |
| `knock` | стучать в окно N с | слаг окна, секунды | ходячие, птицы | у вороны — штурм окна (`crow_siege`), у сектанта — новый клип | Ф2 |
| `breach` | выбить дверь | слаг двери | сектант | писать заново: штурм безумца удалён вместе с ним 11.10 (код — git до шага `remove-madman`) | Ф2 |
| `say` | сказать / звук | текст или id звука | все | квикчат-реплика над головой / SFX | Ф2 |
| `await` | ждать условия | условие события (игрок вошёл/вышел, время, свет) | все | те же `ZoneCondition` | Ф2 |
| `react` | реакция на игрока | см. §2 | все | `CreatureSenses` → переключение шага | Ф3 |

Правило: действие НЕ знает про редактор — у записи есть список полей, и
карточка строит их сама (как `MonsterSpawnFields` сегодня).

## 5. Данные

Сценарий хранится в `ZoneEvent` (событие зоны), новые поля сериализуются тем
же `JsonUtility` вместе с уровнем:

```
ZoneEvent (template = "life")
  monster, who            — актёр (есть)
  триггеры/условия        — есть
  spawn: { mode: mark|hidden|offscreen, mark, zone, face }
  steps: [ { kind: go|go_zone|go_object|wait|roam|toggle|door|vanish, mark, zone, slug,
             move: walk|run, seconds, mode,
             when: [ZoneCondition], chance: 100, onFail: skip|retry|goto|end, failStep, failSeconds } ]
  repeat: once|loop|back  — повтор шагов (как у ZoneRoute)
  exit:  { kind: vanish|vanish_unseen|go_vanish|stay_roam|stay, mark, zone }
  reactions: [ { on: see|hear, kind, seconds, mark } ]
```

- Маркеры и зоны — без изменений в данных (`MarkData` как есть).
- **Миграция** (правило 5 `tavern-game`): при загрузке уровня `monster_spawn`
  + `ZoneRoute` с тем же `who` → один сценарий (появление из события, шаги из
  маршрута, уход «остаться»); старые «Появление/Исчезновение вороны» уже
  переводятся в `monster_spawn` — цепочка та же. Блок «Перемещения» в
  карточке зоны после миграции не нужен.
- Полезная мелочь: `who` даётся само (`<вид>_<N>` по уровню), чтобы сценарий
  не требовал придумывать имя.

## 6. Редактор

- **Карточка сценария** — в списке событий зоны (та же инфраструктура
  карточек: заголовок-сводка, раскрытие, перетаскивание, удаление), разделы
  по §2. Шаги — строки «3 · шагом · стоять 8 с, смотреть в окно
  window_kitchen», перетаскиваются; «Добавить шаг» → выбор «Куда»; внутри
  шага «Добавить действие» → дропдаун каталога, поля действия ниже.
- **Дропдауны вместо имён**: маркеры — номера с зоной; объекты — слаги
  объектов нужного атрибута рядом с зоной (двери, окна, `sittable`,
  «включается»); актёры — список видов.
- **Карточка маркера** — §3.
- **Сводка в заголовке**: «Сектант sectant_1: каждый вход, ночь · 4 шага ·
  уходит, когда не видят». Проблемы красным, как у событий сегодня
  (`EventProblem`): нет маркера, нет объекта, нет имени.
- **Статус в F1 → «События зон»**: «sectant_1: шаг 2/4 — стоит у окна, 5 с»
  — через `Template.Status`, как у Тени.

## 7. Рантайм

- `ZoneEventRunner` стартует сценарий как событие: `Start` → появление
  (`CrowZoneSpawn.Spawn` по виду) → на существо вешается `LifeActor`
  (обобщение `SectantWalker`: шаги, действия, повтор, уход); `Running` —
  пока актёр жив и сценарий не завершён; `Stop` (условия сняты / выход) —
  по настройке: продолжать / уйти.
- Муверы: ходячие — `MonsterNav.Flood/PathTo` + рельеф (как у `SectantWalker`);
  птицы — `CrowFlight` с адаптером «куда лететь дальше» (сегодня он сам
  ходит по `ZoneRoute`, станет брать шаги у `LifeActor`).
- Действия — реестр (§4); у каждого `Start/Tick/Stop`, длительность и
  «можно ли прервать» (реакцией).
- Чувства — `CreatureSenses` (есть), реакции Ф3 читают `SeesPlayer/HearsPlayer`.
- Правила существ сохраняются: гейт этажа, замирание вне кадра, одно имя =
  один актёр («имя занято — Skip»).
