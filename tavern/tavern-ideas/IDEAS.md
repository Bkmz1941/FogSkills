## Живые зоны и адреса клеток (2026-09-09) — предложено, ждёт ответа

- **Суть.** «Динамическая зона» — тот же `ZonePiece`, но в своём слое
  `ZoneKind.Live` (четвёртый, чтобы не спорить за клетку с ручной разметкой
  «Окружения»), который создаёт и правит КОД, а не редактор: в Grid три
  вызова — `ZoneLive.Spawn(slug, cells, флаги стихии)`, `zone.Grow(cell)`,
  `zone.Shrink(cell)`, `ZoneLive.Remove(zone)`; каждая правка клетки сама
  ставит/снимает объёмы стихии (как сегодня редактор зоны) и будит соседей.
  Сохраняется как обычная зона (kind + клетки + флаги) — пожар переживает
  сейв/лоад без новых полей. Модуль огня (`Cozy.Fire`, сборка выше Grid, как
  Cooking; Grid о нём не знает) держит правила: тик раз в игровую минуту,
  соседняя клетка загорается по флагу `flammable` дефа/травы с перевесом по
  ветру и штрафом от дождя, клетка выгорает по таймеру → `Shrink` + чёрная
  напольная накладка, тушение водой → `Shrink`.
- **Адреса клеток** (согласовано с ilya-a2 09.09 вечером, инструмент дебага
  делает она по просьбе Ильи). Большая клетка сетки земли, индекс как у
  реестров стихий (`GridSnap.Cell(p, ground.Origin, cs)`); `A1` = клетка (0,0),
  буквы по X как в Excel (A…Z, AA…), числа по Z = z + 1; этаж через слэш
  только выше земли: `K7`, `K7/2` (номер = индекс уровня + 1). Отрицательных
  у земли нет; переякорка сетки просто перенумерует — это дебаг, не сейв.
  Две чистые функции в `GridSnap.cs` (`Address`, `TryParseAddress`), без
  нового файла; подсветка квадрата под курсором сквозь всё и подпись — её
  компонент. Живые зоны берут адреса оттуда же.
- **Что даёт игроку.** Пожар ползёт по двору к дому, ветер решает куда, можно
  тушить ведром по клеткам, выгоревшее остаётся чёрным; сценарий может сказать
  «пожар в K7…L8 через час».
- **Цена.** Живые зоны + адреса + дебаг — вечер (Grid, ilya-ad); правила
  распространения/тушения — вечер-два у модуля. По кадру: горящая клетка ~38
  шаров + свет + звук; при 20 клетках свет и звук надо капать (свет у 4–6
  ближайших к игроку клеток или один на зону, звук — один источник на зону).
  Сейв: поле `kind` уже есть, новых нет.
- **Что ломает.** Ручная зона огня и живая могут лечь на одну клетку → правило
  «живая побеждает и гасит ручную по клетке» либо «не расти туда, где объём
  огня уже стоит».
- **Дешевле / смелее.** Дешевле — без слоя: живая зона = зона окружения с
  флагом `live`, но тогда спор за клетку с ручной разметкой. Смелее — «поле
  пожара» без зон, реестр горящих клеток прямо в модуле, но тогда сейв,
  редактор и дебаг не достаются бесплатно.
- **Статус.** Предложено, ждёт ответа на два вопроса: темп пожара для игрока
  (минуты и тушение или секунды и бегство) и общий ли API живых зон для
  тумана/дождя/культа.

## Проверка решения в стычке (2026-09-16) — решения приняты, ждёт «делаем»

- **Суть.** Каждый вариант стычки — проверка характеристики (1–10) против
  сложности (0–10): значения решают 90 % случаев, 10 % — случай. Провал
  отменяет решение и запускает сцену 4 «успешная атака»; за попытку всегда
  снимается энергия (своя у каждого решения, по умолчанию 20), при успехе —
  обычная цена сцены. Половина уже есть: `Chance`/`Fail` в графе, плашки
  цены под кнопками, всплывашки над героем.
- **Игроку.** Над кнопкой «Проверка на ловкость · 90 %» — он видит цифру и
  решает, а не гадает (столп 5: серые кубики, напряжение без графики). Клик →
  полсекунды штамп «УСПЕХ»/«ПРОВАЛ» на кнопке, при провале слово над
  героем, потом сцена. Ставка честная: дёшево и рискованно против дорого.
- **Что стоит.** Механика + подписи + штамп + ползунки — один вечер;
  характеристики героя — новое поле статов и вкладка «Игрок»; отдельные
  сцены провала под каждый вариант — по вечеру в Blender каждая, потом.
- **Минимальная версия.** Одна характеристика «ловкость», общая сцена
