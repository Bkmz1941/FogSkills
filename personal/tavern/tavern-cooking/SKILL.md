# Готовка «Таверны» — скил домена

Скил-память ТОЛЬКО по готовке. Общие правила проекта (MakeRoom-стиль, Blender —
эталон, КВАДРАТ/ПОДКВАДРАТ, KISS, никаких комментариев в коде, «новое работает
на старом контенте», проверка Unity MCP в начале сессии, не компилировать в
play) — в `tavern-game/SKILL.md`; **читать его первым**, этот — вторым.

## Карта скила

| Файл | Что | Когда читать |
|---|---|---|
| `COOKING.md` | Актуальное состояние домена — 39 разделов в 8 группах: опора и архитектура модуля, модель готовки (ядро), передача и раскладка, жидкости и кофе, блюда и рецепты, чистота и качество, игрок, открытые вопросы. Оглавление — в начале файла | любая задача по готовке: открыть нужную группу, не читать целиком |
| `DESIGN_LOG.md` | Хронология решений (append-only) | grep по теме, не целиком |
| `PLATE_COMBOS.md` | Единый файл комбинаций тарелки (яйца + сосиски), инструменты переноса, расхождения с игрой | любая работа над раскладкой тарелки |
| `SINK_PILE.md` | Груда посуды в мойке целиком | горка, мойка |
| `SINK_PILE.md` | ⭐ ГРУДА ПОСУДЫ в мойке целиком: чаша и пятна, константы `SinkPile`, правила раскладки, память посадок, единый файл `sink_combos.blend`, перенос правок Ильи, проверка по мешам, чего не делать | любая задача про мойку и посуду в ней, ПЕРЕД правкой `SinkPile.cs` и константами |

Правило: новое закреплённое решение — в конец `DESIGN_LOG.md` с датой И
обновить `COOKING.md` (там только актуальное). Кухонные ОБЪЕКТЫ (модели,
размещение, кит) по-прежнему описываются в `tavern-game/BUILD.md` («Кухонная
линия»), здесь — только их кулинарное ПОВЕДЕНИЕ.

⭐ **Тестовый уровень `products_test`** (Илья 18.10) — продукты и готовка проверяются там, кейсы `PT-…` в `tavern-regress/TEST_LEVELS.md`. Новый продукт или механика готовки → кейс туда.

## Код

- Модуль **`Assets/Modules/Cooking/`**, сборка **`Cozy.Cooking`** (ссылки:
  `Cozy.Grid`, `Cozy.Character`, `Cozy.View`). UI готовки живёт в `Tavern.UI`
  (та ссылается на модуль, не наоборот).
- Точка расширения в ядре: `InteractiveObject.FeatureFactories` — список
  `Func<ObjectDef, InteractiveObject, ObjectFeature>`; модуль регистрирует
  фабрику в `CookingModule.Bootstrap` (`RuntimeInitializeOnLoad`), и ядро
  само вешает кулинарные фичи на объекты по их дефу. `Cozy.Grid` про
  `Cozy.Cooking` НЕ знает (зависимость только в одну сторону).
- Предметы еды — `ItemDef` (`Modules/Grid/Inventory/Items.cs`), модели —
  Kenney Food-кит (`Assets/Game/Resources/Food/*.fbx`, ~100 моделей: овощи,
  фрукты, хлеб, мясо, посуда, бутылки).

## Как начинать сессию по готовке

1. `tavern-game/SKILL.md` → проверка Unity MCP → этот файл → `COOKING.md`.
2. Если задача про объект (плита, кастрюля как предмет мира) — ещё
   `tavern-game/BUILD.md` (пайплайн объектов, Blender-first, перенос 1:1).
3. Если про UI — `tavern-game/UI.md` обязателен.
4. Решения — в `DESIGN_LOG.md` здесь; кросс-доменные (объект в стройке,
   UI-экран) — дублировать короткой ссылкой в `tavern-game/DESIGN_LOG.md`.
