# Генерация домов — коттедж

Скил-память домена «дом как объект»: как игра хранит дом, как его прочитать, как собрать новый
и обставить так, чтобы это прошло проверку. Общие правила проекта — `tavern-game/SKILL.md`
(читать первым), законы стройки — `tavern-build/SKILL.md`, подробности элементов —
`tavern-game/BUILD.md` («СБОРКА УРОВНЯ ФАЙЛОМ», «Лестницы», «Крыша двускатная»).

Заведён 28.10.2026. Первый же вечер: коттедж «Котедж 104» воссоздан на отдельном уровне
`house_cottage` (коробка собрана генератором 1:1 по счётчикам, обстановка скопирована из
оригинала без леса) и рядом `house_cottage_gen` — тот же план, обстановка целиком от
генератора; оба — `HOUSE ok`.

## Как игра хранит дом (что надо знать, прежде чем генерировать)

- **Файл уровня** — `~/.config/unity3d/DefaultCompany/Tavern/levels/<имя>.json`, `sceneName` = имя;
  в списке уровней появляется сам. Чтение без подъёма в сцену — мостом
  `LevelIO.Load("<имя>", false)` (так проверяем счётчики и что все дефы найдены).
- **Сетка** 100×100 клеток по 3 м, начало `gridOriginX −120, gridOriginZ −126` (шапка копируется из
  коттеджа). Клетка `(i, j)` → центр `x = −120 + 3i`, `z = −126 + 3j`. Коттедж стоит в клетках
  i 49…52, j 48…52 (x 27…36, z 18…30), крыльцо — столбец i 48.
- **Стена живёт на ребре**: `('x', i, j)` между `(i,j)` и `(i,j+1)` — полотно вдоль X, сторона A = +Z;
  `('z', i, j)` между `(i,j)` и `(i+1,j)` — вдоль Z, A = +X. Числа элементов — `BUILD.md`
  «Числа элементов» (стена `y = L − 0.01 + 1.506`, плита `y = L − 0.1`, scale `(3, 0.2, 3)`).
- **Проём замещает стену** и помнит её отделку (`wallSaved`, `wallPaint*`, `wallPlinth*`); дверь —
  `slug door_N`, стиль 7 WoodModern (материал 1), 8 SteelModern (4), 9 GlassModern (3, балкон);
  окно — стиль 0 White / 2 Pvc, `offset` ±0.48 сдвиг вдоль стены.
- **Отделка коттеджа**: фасад `WoodPlank002`, внутри `WoodPlank001`, ванная `BathSquareTile`
  (плинтус `#F2F0EB`), пол `CottageFloorOak`, пол ванной `BathFloorTile`, низ плит = потолок нижней
  комнаты, верхняя плита (чердак) `BathDeckDark`. Цоколь снаружи только на земле
  (`plinthStyle kind 1, h 0.32, d 0.12, r 0.5`, hex `#94694F`), выше снаружи плинтуса нет, внутри —
  всегда.
- **Лестница с площадкой** = 2 клетки следа, корень на стыке, `rotY` 90 → +X; дырка в перекрытии
  над обеими клетками; выход с площадки вбок. Перила лестницы `stair_rail` — выучены относительно
  корня лестницы. Проём над гостиной (коттедж: клетка (0,3) второго этажа + половина (1,3)) обнесён
  `edge_rail` по 1,5 м, рейка в 0,15 м от края внутри ходимой клетки.
- **Крыльцо** — плиты без потолка в столбце перед входом, `column_post` по наружным углам,
  `lamp_pendant_lantern` под балконом; **балкон** — плиты `ceiling: true` с низом `WoodPlank002`,
  перила по свободным краям, стеклянная дверь (стиль 9) из холла.
- **Крыша** — одна `roofs` запись на весь след, `pos.y` = уровень над верхним этажом, `cellsX/Z`.
- **Объект**: `pos` = корень модели (низ, центр), `rotY` — куда смотрит СПИНА: 0 → +Z (N),
  90 → +X (E), 180 → −Z (S), 270 → −X (W); `number` — порядковый по id; вложенное — `carrierId`,
  `carrierNode`, `carrierPos`, `localPos`, `localRotY` (игра пересаживает по узлу при загрузке,
  `pos` при этом вторичен); `keepPlinth` — стоит у плинтуса; цвета ламп — `pcSet/pcr/pcg/pcb`,
  `palette`.

## ⭐ Законы посадки (сняты с коттеджа 28.10, `learn`)

1. **Напольное у стены: спина на 0,15 м от внутренней грани стены** (обшивка 0,10 + стоп у плинтуса):
   шкаф, тумбочка, холодильник, плита, камин, ТВ-столик, диван, стол письменный, угловая тумба — все
   0,152…0,171 в коттедже. **Режущие обшивку — на 0,01**: кровать (с изменённой длиной), ванна,
   унитаз, стиралка, раковина, вешалка, батарея, стояк. Список по id — `learned.json → gap`; у
   неизвестного объекта берём 0,15 (безопасно: не тонет ни в обшивке, ни в плинтусе).
2. **Настенное сидит на обшивке**: по дереву 0,10 от грани стены, по плитке ванной 0,02. Высота корня
   над полом — выученная по id (`wall_h`: выключатель 1,85–2,14 — выше `wallHeight` дефа 1,35, Илья
   ставил так; розетка 0,90–0,98; бра 0,96–1,24; картина 1,8–1,92; телевизор 1,33; навесной угловой
   1,88; часы 2,14; шкафчик ванной 1,74; полка ванной 1,56; полотенцесушитель 1,72; крючки 1,92;
   держатель бумаги 0,84; гирлянда 1,41; занавес-гирлянда 1,12; счётчик 1,26; полка-планка 1,99).
   У дефа своя `wallHeight` — запасной вариант.
3. **Потолочное** — `y = L + 2,8` (низ плафона 2,5, под плитой 2,9). Одна лампа на комнату до 6
   клеток, две на бо́льшую.
4. **Поверхностное** — `y = L + верх хозяина` (стол 1,17, столешница 1,15, тумбочка 0,79);
   наборы хозяев — выученные с коттеджа: холодильник (кетчуп, масло, колбаса ×2, молоко, яйца ×2 по
   узлам `DoorShelfB`…), угловая тумба (мойка, кофемашина с баком, кувшином, фильтром и гущей,
   кружки, губка, папоротник, ведро внутри), навесной угловой (тарелки стопкой, кофе, фильтры), стол
   (миска с яблоками, шоколад), камин (10 поленьев в топке, свеча, спички и герань на полке), кровать
   (мишка), тумбочка (фонарик с батарейками в ящике), шкафчик ванной (четыре блистера, аптечка,
   бинт), раковина ванной (мыло, стакан, паста, бритва, гель, пена), стиралка (таз, полотенце),
   консоль ванной (шампуни, бумага), стол письменный (будильник, папоротник, рюкзак), ТВ-столик
   (пульт, будильник), стеллаж (книга), столик балкона (журнал), уличный щиток (трансформатор).
   Набор переносится вместе с хозяином: смещения в системе хозяина, `carrierNode/localPos` как в
   оригинале, `carrierPos` пересчитан.
5. **Угловой модуль** (угловая тумба, угловой навесной, `cornerModule`): крыло ВЛЕВО (локальный −X).
   Угол NE → стена E (yaw 90), NW → N (0), SE → S (180), SW → W (270); левый торец в углу, крыло
   уходит по второй стене на глубину `d` (2,6 у тумбы). Холодильник — рядом по той же стене, плита —
   за торцом крыла по второй стене, в линию (модули касаются, допуск −0,02).
6. **Зона двери свободна**: прямоугольник 1,7 × 1,6 м перед дверью с обеих сторон, по стене
   ±0,95 м от оси двери не ставим; открытый проём (без стены) — 3 × 1 м. Лестница: обе клетки следа
   + 1,2 м перед входом на марш.
7. **Окно**: высокое (≥ 1,3 м: шкаф, холодильник, стеллаж, кровать по умолчанию) под окно не
   ставится; низкое (батарея, стол, диван, тумбочка) — можно. Батарея — под окном на 0,01 от стены,
   шторы (`curtain_drapes`) и жалюзи (`blind_venetian`) — на окне у грани стены, из проверок
   пересечений исключены.
8. **Стул под столом и кресло у стола — не пересечение**, угловой диван — L-образный, его bbox не
   считается; всё остальное напольное — без заходов друг в друга и сквозь стены (допуск 0,1 — так
   стоит эталон Ильи: шкаф и стол письменный в спальне заходят на 7 см по bbox каталога).

## Как пользоваться

```
cd ~/.claude/skills/tavern-houses
python3 housegen.py passport "Котедж 104"                     # что где: этажи, комнаты, типы, обстановка
python3 housegen.py learn                                       # переснять learned.json с коттеджа (после правок Ильи в доме)
python3 housegen.py build plans/house_cottage.json house_cottage --objects-from "Котедж 104"   # коттедж без леса, обстановка 1:1
python3 housegen.py build plans/house_cottage.json house_cottage_gen --seed 1                  # тот же план, обстановка генератора
python3 housegen.py new house_rnd7 --seed 7 [--nx 5 --nz 6 --porch S --no-void]              # новый коттедж + plans/house_rnd7.json
python3 housegen.py check house_rnd7                            # HOUSE ok / FAIL с причинами
python3 housegen.py edit house_rnd7 list                        # номера объектов по комнатам
python3 housegen.py edit house_rnd7 move 12 0.5 0 90            # сдвинуть №12 на +0,5 по X и повернуть на 90 (набор едет с ним)
python3 housegen.py edit house_rnd7 remove 12                   # снести вместе с набором
python3 housegen.py edit house_rnd7 add спальня home_shelving wall:W   # добавить по правилам посадки (с набором)
python3 housegen.py edit house_rnd7 swap 12 home_wardrobe_slide        # заменить объект на другой на том же месте
```

Отчёт `build`/`new` — строка на объект: комната, id, как встал («стена E t=19.50», «угол NE», «рядом
с …», «за крылом …», «набор …», «НЕ ВСТАЛ (…)»). «НЕ ВСТАЛ» — не ошибка файла, а честный отказ:
места нет (2×2 спальня не вмещает стеллаж), окно на нужной стене, зона двери.

Проверить в игре без смены уровня Ильи — мостом:
`LevelIO.Load("house_cottage", false)` (счётчики, `FurnitureCatalog.ById` на каждый объект).
Открыть уровень в редакторе — только Илья или по его слову (`tavern-game`: уровень в редакторе не
меняем). Настоящая постановка через `ComputeObjectPose` (как `tavern-night/night_place.py`) — в
очереди: проверить сгенерированные позы живым конвейером в своём play.

## ⛔ Правила

1. **Пишем только `house_*`**: `Level.write` отказывает любому другому имени; `edit` — только
   `house_*`. Уровни Ильи (level1, «Котедж 104», тесты) не перезаписываются никогда.
2. **Эталон — «Котедж 104»**: `check` обязан быть зелёным на оригинале (HG-C01); правило проверки,
   красящее эталон, — неверное правило, а не баг коттеджа. Расхождение с тем, как ставит Илья,
   лечим в `learn`/законах, а не особыми случаями.
3. **Схема записи — из `templates.json`**, не руками: новое поле сейва появляется у игры —
   удалить `templates.json`, он пересоздастся из коттеджа.
4. **Габариты — из `catalog.json`**, снятые с живых моделей; новая модель или изменённый размер —
   переснять (`catalog_dump.py`, нужен play).
5. **Новое работает на старом**: план коттеджа (`plans/house_cottage.json`) — регресс-кейс HG-B:
   коробка по нему обязана давать 39 стен, 63 плиты, 7 дверей, 5 окон, 1 лестницу, 1 крышу.
6. **Никаких комментариев в коде, KISS** — общие правила `tavern-game`.

## Чего пока нет (очередь)

- проверка поз НАСТОЯЩИМ конвейером `ComputeObjectPose` в play на `house_*` (раннер
  `tavern-night/night_place.py` — образец; ждёт свободного play или ночи);
- полуплита (коттедж: половина клетки (1,3) второго этажа) — план кладёт целую плиту;
- `open`-рёбра между комнатами одного этажа понимает только `build` (паспорт сливает гостиную и
  кабинет коттеджа в одну комнату через открытый проём у лестницы — как и игра при заливке);
- второй тип дома (не коттедж), подвал, два марша, мансарда с жилой комнатой;
- вставка сгенерированного дома в существующий уровень (`--into`), сейчас — только свой уровень.
