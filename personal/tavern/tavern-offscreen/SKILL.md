# Жизнь за кадром — уровни без игрока и переходы между ними

Скил-память домена. Общие правила проекта — `tavern-game/SKILL.md` (первым).
Живой уровень (правила `[условия] → [действия]`, планы существ, пульт) —
`tavern-life`, его не дублируем: здесь только то, что происходит, когда героя
на уровне НЕТ, и как он между уровнями ходит.

## Чего хочет Илья (его слова, 11.10)

- «память мира ок» — покинутый уровень помнится, вернулся — всё как оставил.
- «сделай скил — будет меняться на фоне на уровнях в локациях что-то в
  зависимости от времени, нужен механизм работы с локациями где нет игрока
  для событий — надо придумать как с правилами для монстров движений —
  примерно такое же — время, кто, что сделал типо, где оказался, все в скил и
  в дебаг — попробуем».
- Про переходы: «остальное ок, делай, точку перехода и в Уровни чтобы —
  свободное расставление» — точка перехода ставится свободно, из меню
  «Уровень», как маркер респавна.

## Словарь

| Слово | Что это |
|---|---|
| **Уровень / локация** | файл уровня со слагом (`level1`, `lihovo`); у Ильи «локация» = уровень-площадка |
| **Живой уровень** | тот, что сейчас собран в сцене; на нём работают `tavern-life` (правила, планы, чувства) |
| **За кадром** | уровень, который герой покинул: сцены нет, есть снимок в памяти (`LevelIO.Visited[слаг]`) и строки «за кадром» |
| **Строка** | `[HH:MM][кто][что][где]` — что случается на уровне каждый день в это время, пока героя там нет |
| **Запись (факт)** | строка, чьё время прошло, пока героя не было: лежит в журнале уровня, ждёт применения |
| **Журнал** | `Offscreen.Levels[слаг].Facts` — «время, кто, что сделал, где оказался», с отметкой «применено» и результатом |
| **Точка перехода** | маркер `travel_marker` (плитка с носиком) или зона `to_<слаг>` — где герой уходит на другой уровень и где появляется, придя оттуда |

## Как это устроено

### 1. Переходы между уровнями (11.10; подробно — `tavern-story`, «Переходы между уровнями»)

- **Зона** со слагом `to_<слаг уровня>` (любого вида) — площадь перехода:
  название зоны = подпись места, описание = подзаголовок.
- ⭐ **Маркер «Точка перехода»** (Илья: «свободное расставление») — объект
  `travel_marker` из палитры «Уровень → Спавны» рядом с «Маркером респавна»:
  синяя плитка по подквадрату с носиком-направлением; виден и кликается только
  в стройке при включённом слое спавнов (как `SpawnPoint.Shown`). В карточке
  кнопка **«Куда…»** → «Название места» (`io.Title`) и «Куда — слаг уровня»
  (`io.Slug`); оба поля уже живут в сейве объекта (`ObjectData.title/slug`).
  Радиус срабатывания 1,6 м (`TravelPoint.Reach`), тот же этаж.
- **Срабатывание:** герой стоит в зоне/у маркера 1 с (`TravelLook.HoldSeconds`)
  с карточкой над головой → `SceneLoader.Travel(слаг, подпись)`. В стройке
  переходы не срабатывают. Цели нет — карточка «Уровня «x» нет», остаёмся.
- **Экран:** затемнение 0,35 с → чёрная карточка «название места» +
  «Загрузка…» → сборка уровня (кадр стоит) → карточка не меньше 1,8 с →
  проявление 0,6 с. Время мира стоит (`ViewState.SetTimeScale`), после — часы
  +0,5 ч (`TravelLook.Hours`).
- **Прибытие:** в целевом уровне ищется парная точка, ведущая ОБРАТНО: зона
  `to_<откуда>` (центр, лицом к центру карты) или маркер с «Куда» = откуда
  (на него, лицом по носику плитки). Нет пары — точка спавна, нет и её —
  центр сетки. Парная точка молчит, пока герой из неё не выйдет
  (`SceneLoader.ArrivedAt`). Инвентарь, одежда, руки едут с героем.

### 2. Память мира (принято Ильёй 11.10)

При уходе уровень собирается в память: `LevelIO.Remember(имя, слаг)` →
`Collect(toDisk:false)` → `LevelIO.Visited[слаг]`. Файлы уровней и краска
НЕ пишутся (краска при сборе уходит в `temporaryCachePath`). Возврат —
`LevelIO.LoadBySlug`: сначала память, потом сейв/поставочный по слагу. Новая
игра из меню (`SceneLoader.Run`) чистит память и журналы.
Не помнится: правки краски земли (читается с диска), существа из событий зон
(`LevelIO.Unsaved`), прогресс заданий (он и так не в сейве).

### 3. Строки «за кадром» — формат

Хранятся в файле уровня (`LevelIO.AiOffscreen`, поле `aiOffscreen`), пишутся
во вкладке F1 → ИИ → «За кадром», сохраняются вместе с уровнем. Синтаксис —
как у правил `tavern-life`: токены в квадратных скобках, английские слова,
по одной строке на событие, `#` — комментарий.

```
[HH:MM][кто][что][где]
```

| Поле | Что | Примеры |
|---|---|---|
| `[HH:MM]` | время суток, когда это случается КАЖДЫЙ день, пока героя нет | `[21:00]`, `[06:30]` |
| `[кто]` | существо: `вид имя` (`sectant sectant_1`) или имя с видом-префиксом (`sectant_1`, `crow_2`); виды — crow, owl, robin, sectant. Для действий с объектами «кто» — свободный текст (кто это сделал, для журнала) | `[sectant sectant_1]`, `[crow_2]`, `[кто-то]` |
| `[что]` | `appear` — появился; `go` — оказался (без пути, сразу); `leave` — ушёл с уровня; `on`/`off` — включил/выключил; `open`/`close` — открыл/закрыл | |
| `[где]` | для appear/go — зона или `зона/marker_N`; для on/off/open/close — системное имя объекта (`meter_outdoor_1`, `door_3`, `fridge_1`); у `leave` поля нет | `[monster_zone_2/marker_3]`, `[meter_outdoor_1]` |

Пример для «Сосен»:
```
# ночью к дому приходит сектант, гасит счётчик, к утру уходит
[21:00][sectant sectant_1][appear][monster_zone_2/marker_1]
[21:30][sectant_1][go][monster_zone_2/marker_3]
[22:00][sectant_1][off][meter_outdoor_1]
[05:30][sectant_1][leave]
```

Непонятая строка — ✗ с причиной в проверке вкладки, не исполняется
(`Offscreen.Parse`, тест `LifeRulesParseTests.Строки_за_кадром_разбираются_а_кривые_помечаются`).

### 4. Тик и журнал

`OffscreenRunner` каждый кадр (`Offscreen.Tick`): для каждого уровня в памяти,
КРОМЕ живого, строки, чьё время часы мира только что пересекли
(`Weather.Hour`, переход через полночь учтён), становятся записями журнала
`Offscreen.Levels[слаг].Facts` — «время, кто, что, где» — и строкой в игровые
логи «За кадром «slug»: 21:00 sectant_1 appear …». Уход фиксируется
`Offscreen.Left(слаг)` (`LeftAt` для вкладки). Журнал держит 80 последних
записей, неприменённые не выкидывает.

### 5. Применение при возвращении

`Offscreen.Arrived(слаг)` → `Apply`: записи сворачиваются в КОНЕЧНОЕ
состояние, промежуточное не разыгрывается — за кадром важно «где оказался»:
- по каждому существу — последняя запись: `leave` → убрать
  (`CrowZoneSpawn.RemoveCreature`), иначе поставить у маркера/в зоне
  (`CrowZoneSpawn.Place(kind, who, zone, Any, mark, "offscreen", …)`; уже
  стоящее с тем же именем сначала убирается);
- по каждому объекту — последнее из on/off/open/close: `PowerFeature`,
  `WallSwitchFeature`, `FireplaceFire`, `AccessFeature`, `DoorPiece`,
  `WindowPiece` — те же ручки, что у шагов планов `tavern-life`.
Результат пишется в запись (`Result`: «нет зоны …», «… не включается») и в
игровые логи «За кадром «slug» применено: …».

### 6. «Прожить N часов здесь» — проверка без переходов

Во вкладке: ползунок «Часов без игрока» и кнопка «Прожить эти часы здесь и
применить» → `Offscreen.Simulate(слаг, часы, текст)`: строки, чьё время
попало в последние N часов (24 = все), записываются в журнал по порядку и
применяются к ЖИВОМУ уровню. Так Илья проверяет строки, не уходя с уровня.

### 7. Вкладка F1 → ИИ → «За кадром» (`HudUI.Offscreen.cs`)

Уровень и часы · поле строк (моноширинный редактор, как у правил) ·
«Сохранить строки» · проверка построчно ✓/✗ · тумблер «Жизнь за кадром» ·
ползунок часов + «Прожить…» · «Журнал за кадром»: по уровню в памяти — «ушёл
в HH:MM» и записи (✓ применено / … ждёт, результат) · «Очистить журнал».

## Правила домена

1. **За кадром — только конечное состояние.** Никаких планов и путей для
   уровня без сцены: запись говорит, где существо ОКАЗАЛОСЬ и что с объектом
   СТАЛО. Хочется «шёл и увидел» — это живой уровень, `tavern-life`.
2. **Один словарь с живым уровнем.** Имена существ, зоны, маркеры, системные
   имена объектов — те же, что в правилах и пульте. Новое действие — сначала
   ручка в `CreaturePlan`/фиче объекта, потом слово здесь.
3. **Файлы уровней переход не пишет.** Память — ОЗУ на забег; строки «за
   кадром» — часть уровня, пишутся только «Сохранить» Ильи.
4. **Всё видно:** журнал во вкладке, строки в игровых логах с префиксом «За
   кадром», результат применения в записи.
5. **Предсказуемость:** строки — расписание, одно и то же каждый день; без
   случайностей, без модели.
6. **Новое работает на старом контенте:** уровень без `aiOffscreen` — просто
   пустой список; старый сейв читается (поле в конце).

## Чего нет (v2 — по слову Ильи)

- Уровни, где герой ещё НЕ БЫЛ, за кадром не живут: записи копятся только для
  уровней в памяти. Нужны «все уровни мира с их строками» при старте забега —
  список слагов + чтение `aiOffscreen` из файлов.
- Дни: строки суточные, «на третий день» нет (условие `[day N]`).
- Предметы: «взял», «переложил», «оставил записку» — нет ручек.
- Существа, оставшиеся на живом уровне в момент ухода, не продолжают планы:
  при возвращении они там, где их сохранила память; строки за кадром могут
  их переставить (`go` по имени).
- Склейка с `[правила]`: одно описание и для живого, и для закадрового
  уровня (`[away]`-условие) — пока два текста.
- Журнал не сохраняется между запусками игры (как и память мира).
- ~~Сборка уровня синхронная: карточка перехода стоит 10 с~~ — с 17.10 сборка
  по 7 шагам с полосой прогресса, растения и облака тумана досыпаются после
  (раздел «Переход под капотом» ниже).

## Чек-лист: новая строка за кадром

1. Имя существа и зона/маркер существуют в уровне (словарь во вкладке «ИИ»).
2. Строка ✓ в проверке вкладки «За кадром».
3. «Прожить 24 ч здесь» — существо стоит где надо, объект в нужном состоянии,
   в логах «За кадром … применено» без «— …».
4. Круг с переходом: уйти, перевести часы через отметку (F1 → Погода или
   скорость времени), вернуться — то же состояние.
5. «Сохранить» уровень (Илья), чтобы строки остались в файле.

## ⭐ Указатель-переход `old_signpost` — точка входа и выхода с именем (13.10, ilya-27)

Илья 13.10: «Осмотреть и Перейти кнопки — перейти переноси в другую карту, в Редактировании выпадающее меню для выбора уровня и точки, где появляешься (системное имя); поставлю — и будет считаться, что на уровне есть точка выхода и входа; системное имя уникальное на все уровни», «Таб — Переходы».

- Деф с флагом `ObjectDef.travelGate` (у «Указателя старого»). `TravelPoint` вешается и на такие дефы (`IsGate`), но они НЕ срабатывают по близости (`At`/`GateFrom` их пропускают) — только кнопкой.
- Имя точки `InteractiveObject.Gate` = `<слаг уровня>_<id>_<номер>` (`level2_old_signpost_1`), выдаётся в `TravelPoint.Start`, если пусто; уникально на все уровни, потому что слаг уровня уникален. Куда: `Slug` = слаг уровня, `GateTo` = имя точки там. В сейве `ObjectData.gate/gateTo`.
- Карточка в игре: «Осмотреть» (`examinable`) и «Перейти» (активна, когда заданы уровень и точка) → `TravelPoint.Go` → `HudUI.GoThroughGate` → `SceneLoader.ArriveGate` + `Travel`. Прибытие: `SceneLoader.Arrive` ищет `TravelPoint.Named(ArriveGate)` и ставит героя в 1,6 м перед указателем лицом от него; не нашёл — прежняя логика (парная зона/маркер, спавн).

### Что происходит по порядку (`SceneLoader.RunTravel`)

1. Время мира стоп, затемнение 0,35 с, карточка «название места — Загрузка…».
2. `LevelIO.Remember(имя, слаг)` → `Collect(toDisk:false)` — снимок покинутого уровня в `Visited` (**790 мс** на level1: `FindObjectsByType` + `Snapshot` по 28 тыс. объектов, ~0,5 КБ записи на каждый). `Offscreen.Left`.
3. `LevelIO.LoadBySlug` — из `Visited`, если уже были (0 мс), иначе файл 76–90 МБ через `JsonUtility` (**0,66 с**).
4. `GridCursor.RestoreLevelSteps` — 7 шагов, между ними кадр, полоса 0,2 → 0,85: `Clear` (снос прежнего уровня) → `Ground` (земля, копка, покраска) → `Slabs/Walls` → `Doors/Windows/Stairs` → `Objects` (растения без пар, содержимого, вложения и названия откладываются в `_pendingPlants`; облака тумана — ленивые) → `Zones/Roofs/Water` → `Textures/Sync` → `LightZones.MarkScene` (**419 мс** на полном уровне) → `Player` → `GC.Collect` + `UnloadUnusedAssets`. Лог прошлого перехода: `[Переход] level2 → level1: память 790 мс, чтение 662 мс, сборка 7657 мс`.
5. `Arrive` — указатель, зона `to_<откуда>` (её маркер) или точка спавна; `FlushPlantsNear(герой, 40 м)` и `FogView.BuildNear(Reach + 8)` ещё под экраном.
6. `Offscreen.Arrived`, часы +0,5 ч, `CameraFollow.SnapToTarget`, карточка не меньше 1,8 с, проявление 0,6 с.
7. Уже в игре: `GridCursor.Update` каждый кадр досыпает растения ближние-первыми по бюджету `PlantBudgetMs` (3 мс) и строит облака тумана ближе радиуса рендера. На level1 это 24 тыс. растений ≈ 25 с, кадр на это время на 4–5 мс дороже, потом 200+ FPS. Смотреть: F1 → Мир → «Уровни».

### Три бага, найденные 17.10 (ilya-6d), и решения

- **P1105** — `FurnitureCatalog.ById` создавал новый `ScriptableObject` на каждый вызов: 28 тыс. дефов-сирот на загрузку, после сноса уровня они висели; `ByPickupItem` (вес инвентаря, хотбар) плодил ещё ~27 в секунду в покое (57 493 → 92 582 дефов за 20 минут). Решение: один общий деф на id (`_shared`), свежие только персоны и телефоны; дефы никто не правит (`SwapModel` — на копии). После: 958 дефов при тех же объектах.
- **P1106** — `InteractiveObject.OnDisable` → `List.Remove` по всему реестру: 0,28 мс на каждый снос свежего объекта (клубы тумана в ловушке, брошенные предметы). Решение: подсказка-индекс `_allSlot` и `ReferenceEquals`; снос уровня — `InteractiveObject.Teardown` + `FinishTeardown` одним `RemoveAll`.
- **P1107** — досыпка пересортировывала 24 тыс. записей `List.Sort` с лямбдой на каждые 10 м хода: 14–17 мс рывок. Решение: подсчёт по полосам дальности 4 м (`SortPendingNearestLast`), 1,7 мс, без мусора.
- Мелочь: три `GetComponent` с null в `FloorPieceView.Attach` строили строку ошибки в редакторе (1,9 КБ на объект) → `TryGetComponent`.
- Ранее в тот же день (ilya-ed): снос клуба тумана пересобирал соседей (`CellVolumes.Teardown`), растения двигали `AllRevision` (P1100 — кадр 29 мс в досыпку), зоны терялись при каждой загрузке (P1104).
