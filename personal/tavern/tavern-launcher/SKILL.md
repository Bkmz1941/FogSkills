## Архитектура (целевая)

```
Лендинг (index.html, nginx на VPS) ── кнопка «Скачать» ──► R2: launcher/Tavern-Setup.exe
                                                                    │
Лаунчер (Electron) ── login ──► tavern-server (VPS, HTTPS) ◄── /me ─┤ игра проверяет токен
      │  versions/latest → manifest.json                            │
      ▼                                                             │
R2: builds/<platform>/<version>/files/…  ── скачал, сверил sha256 ──► Tavern.exe --token <jwt> --api <url>
```

Ответственность: сервер знает пользователей и версии; R2 хранит файлы;
лаунчер качает и запускает; игра только проверяет токен через уже
существующий `FetchMe`.

## Компоненты

### 1. Сервер — расширяем `tavern-server`

Добавить (feature-first пакеты по образцу существующих):

| Эндпоинт | Кто зовёт | Что |
|---|---|---|
| `GET /api/tavern/v1/game/versions/latest?platform=windows-x64&channel=test` | лаунчер | `{version, manifestUrl, baseUrl, size}` |
| `GET /api/tavern/v1/game/versions` | лаунчер, лендинг | список активных версий по платформам |
| `POST /api/tavern/v1/admin/versions` (requireAdmin) | скрипт публикации | регистрирует версию: платформа, канал, версия, `manifestUrl`, `baseUrl` |
| `POST …/auth/register` + подтверждение почты через Resend | лаунчер | **только если открытая регистрация** (вопрос 3). Для закрытого теста — юзеров заводит Илья миграцией/скриптом, эндпоинт не нужен |
| `POST …/auth/refresh` | лаунчер | необязательно: TTL 7 д хватает на MVP, лаунчер просто просит перелогин |

Таблица `versions (id, platform, channel, version, manifest_url, base_url,
size_bytes, published_at, active)`. Токен для игры — тот же accessToken, что у
лаунчера, ничего нового. Rate-limit на `/auth/login` (WebFlux-фильтр или nginx
`limit_req`).

Деплой: VPS, Docker Compose с двумя сервисами (`postgres:17`, приложение из
`bootJar` на образе JDK 25), nginx перед ним с Let's Encrypt. Java-процессу
хватит 1 ГБ.

### 2. Хранилище билдов — Cloudflare R2

Трафик наружу бесплатный, платим только за объём. Раскладка бакета:

```
builds/<platform>/<version>/manifest.json
builds/<platform>/<version>/files/<путь как в сборке>
launcher/latest.yml            ← electron-updater (generic provider)
launcher/Tavern-Setup.exe      ← фиксированное имя, лендинг ссылается сюда
launcher/Tavern-Setup-<ver>.exe
```

Бакет публичный на чтение (файлы и так для игроков), токен на запись — один,
только у скрипта публикации, права на один бакет. Запасной вариант для
закрытого теста: раздавать с того же VPS через nginx (у Hetzner большой лимит
трафика), но диск маленький — держать две последние версии.

### 3. Скрипт публикации

Один скрипт (Python, лежит рядом с сервером или в репо лаунчера — вопрос 6):
1. кладёт `BuildRequests/<platform>_prod.request`, ждёт `.done`;
2. обходит папку сборки, считает sha256 и размер каждого файла, пишет
   `manifest.json` (формат ниже);
3. `rclone copy` файлов и манифеста в R2;
4. `POST /admin/versions` с админским токеном.

Без него каждая выкладка — ручная возня, поэтому делается в фазе 1, раньше
лаунчера: пока лаунчера нет, версия проверяется `curl` + `rclone`.

### 4. Лаунчер

**Стек: Electron + React** (решение предлагается, вопрос 4). Причина: вся
логика скачивания — потоки, `fs`, `crypto` на Node, который мы пишем везде
(NestJS, game-engine-rng). Минус — установщик ~150 МБ. Альтернатива Tauri: в
десять раз легче, но скачивание писать на Rust.

Экраны — три, больше не надо: вход; главный (версия, прогресс, кнопка
«Играть»/«Скачать»/«Обновить»); настройки (папка установки). Ни новостей, ни
друзей, ни магазина.

Логика:
- **Вход** → `auth/login`, токен в `safeStorage` (не в plaintext-файле).
- **Проверка** → `versions/latest`, скачать манифест, сравнить с локальным
  манифестом (`installed.json` в папке игры): по sha256 понять, какие файлы
  качать. Первая версия — пофайловая, без чанков.
- **Скачивание** → во временную папку, HTTP Range для докачки, sha256 после
  каждого файла, потом атомарная замена (rename). Обрыв — продолжить с места.
- **Запуск** → `spawn(Tavern.exe, ['--token', jwt, '--api', apiUrl])`,
  лаунчер сворачивается, ждёт выхода процесса.
- **Самообновление** → `electron-updater`, generic provider на `launcher/` в R2.

### 5. Установщик и подпись

`electron-builder`: NSIS под Windows (собирается и на Linux), AppImage/deb под
Linux. Подпись: самый дешёвый путь — Azure Trusted Signing по подписке (~10 $/мес,
нужна проверка личности/компании; ключ не лежит на диске). Классический
OV-сертификат дороже, с 2023 только на аппаратном токене. Для закрытого теста
можно **не подписывать**: тестеры один раз жмут «Всё равно запустить».
Репутация SmartScreen копится неделями даже с подписью. Подписывать удобнее с
Windows или в CI на gitlab.agg.one.

### 6. Лендинг

Один `index.html` в духе `lucky-landing`, на том же VPS под nginx. Кнопка
«Скачать» → `launcher/Tavern-Setup.exe` в R2 (фиксированное имя, никакой
логики). Опционально блок «текущая версия» с `versions`. Форма не нужна.

### 7. Игра — минимальные правки

- `AuthClient.BaseUrl` из константы → значение из аргумента `--api` или
  `StreamingAssets/config.json`; в редакторе и дев-сборке — прежний localhost.
- Разбор `--token`: если есть — `AuthSession.Token = …`, `FetchMe`, при
  ошибке — попап и выход (или офлайн-льгота на N дней — вопрос Илье позже).
  `LoginPanelUI` при токене не показывать. Дев-сборка без токена — как сейчас.
- `insecureHttpOption` — прод только HTTPS.
- Скрипт сборки под Windows по образцу `BuildLinux.cs` + триггер
  `BuildRequests/windows_prod.request` (правило tavern-game о новых файлах:
  спросить Илью, куда класть — в тот же `BuildLinux.cs` или новый файл).
- Standalone → IL2CPP до первой публичной раздачи (сборка дольше, проверить
  под Linux/Windows отдельно).
- `companyName: DefaultCompany` → настоящее имя (нужно установщику и подписи;
  меняет `persistentDataPath` — сейвы дев-уровней переедут, учесть).

## Манифест версии (черновик)

```json
{
  "game": "tavern",
  "platform": "windows-x64",
  "channel": "test",
  "version": "0.1.0",
  "exe": "Tavern.exe",
  "files": [
    { "path": "Tavern_Data/level0", "size": 123456, "sha256": "…" }
  ]
}
```

`path` — относительно корня сборки, разделитель `/`. Лаунчер удаляет локальные
файлы, которых нет в манифесте. Подпись манифеста (ed25519, публичный ключ
зашит в лаунчер) — фаза 5, но поле `signature` заложить сразу.

## Безопасность — чек-лист

Две разные угрозы, ответ Илье 2026-09-20.

**Код в билде у игрока.** Всё, что отдаём, можно вытащить — вопрос цены.
- **IL2CPP вместо Mono** — главная и почти бесплатная мера (Mono
  декомпилируется dnSpy за минуту).
- Ассеты не защищаются (AssetRipper), шифрование бандлов только замедляет.
- Обфускация поверх IL2CPP — не на старте, ломает стектрейсы.
- Никаких секретов в билде: ключей, паролей, админских адресов.
- Токен от пиратства не защищает: файлы на диске, проверку вырежут. Актив —
  игра как продукт, обновления, аккаунты, а не код.

**Исходники и инфраструктура** — гигиена:
- Репо приватные, SSH-ключи, 2FA на GitHub/gitlab, бэкап; секреты в `.env`
  вне гита; попало в историю — ротировать.
- Сервер: вход только по ключу, ufw + fail2ban, автообновления, **отдельно от
  рабочих проектов** (Lucky, краши, Olimp).
- Бэкенд: bcrypt уже есть; лимит на логин; стектрейсы наружу не отдавать.
- Ключ подписи — самое ценное: украдут → вредонос с нашим именем. Trusted
  Signing держит его вне диска.
- Обновления: манифест по HTTPS, sha256 каждого файла до запуска, позже
  подпись манифеста. Иначе взлом бакета = подмена игры у всех разом.
- R2: ключ записи только у скрипта публикации.
- Рабочая машина: шифрование диска, менеджер паролей вместо текстовых файлов
  с паролями в домашней папке.

## Пиратство и оплата (ответ Илье 2026-09-20)

Вопрос: «как защитить игру от взлома и торрента, когда добавлю оплату». Ответ:
полностью — никак, ломают всё вплоть до Denuvo. Лаунчер сам не защищает:
Battle.net и Тарков не крякают, потому что игра **не работает без сервера**.
Это единственная настоящая защита, остальное — замедление.

По убыванию силы:
- **Зависимость от сервера.** События мира в реальном времени (культ и др.)
  уже в дизайне; если мир, прогресс и сейвы живут на сервере (серверные сейвы
  дома уже есть), торрент — пустая оболочка. Цена: только онлайн.
- **Мультиплеер** — крякнутых на официальные серверы не пускают.
- **Право владения на сервере.** Покупка = запись в БД (`users.paid` или
  таблица покупок); лаунчер не отдаёт билд без неё; игра при старте и раз в
  ~10 мин спрашивает `/me` (токен жив, аккаунт оплачен). На IL2CPP патчится
  часами, не минутами.
- **Водяной знак в билде.** Лаунчер при скачивании кладёт id аккаунта в один
  из файлов (или сервер отдаёт персональный файл). Утёк на торрент → знаем
  чей → бан. Дёшево при нашей схеме раздачи.
- **Частые обновления** — торрент устаревает, легальный игрок получает контент.
- **IL2CPP + стрип** — подорожание крякинга.

Не делать: Denuvo (дорого, ломается), самодельные ловушки в коде, шифрование
ассетов, античит на ядре.

Оплата: с лендинга — Xsolla или Paddle (merchant of record: налоги/НДС по
странам на них); Steam — комиссия, но витрина и своя слабая DRM-обёртка.
В любом случае право владения — у нас на сервере, не в файлах игры.

Реальность: крякнут за день-два, если игра выстрелит; пираты почти не
покупали бы и так; пиратство — вопрос удобства (цена, обновления, простота
покупки). На защиту тратить дни, не недели.

Рекомендация: (1) сразу — владение на сервере, проверка токена при старте и
по таймеру, IL2CPP, водяной знак, обновления через лаунчер; (2) решение
Ильи — сколько мира уносить на сервер (вопрос 11).

каждым билдом, пофайловые хеши дают почти полную перекачку; чанковая схема как
в Steam — отдельный проект, для закрытого теста живём с полной перекачкой.
