# Что делать, когда покраснело

## 1. Понять, чьё это (правила соседства целиком — `SESSIONS.md`)

В дереве работают несколько сессий. Прежде чем чинить:

```
git status --porcelain | wc -l        # сколько файлов в работе
git diff <файл> | head -40            # чей это код
```

- Красное в ЧУЖОМ незакоммиченном файле — не чинить. Написать владельцу через
  сообщение сессии, назвать тест и строку. Часто это середина их правки.
- Красное в своём — чинить сразу.
- Не уверен, чьё — спросить, а не гадать: цена ошибки выше цены вопроса.

## 2. Отделить регрессию от новой ошибки

- Тест был зелёным утром? `git log --oneline --since=…` по файлу теста и по
  файлу правила.
- Если правило есть в `INVARIANTS.md` — это РЕГРЕССИЯ. Значит, защита была, но
  дырявая: чинить не только код, но и защиту.
- Если правила нет — это новая история: завести строку в `INVARIANTS.md` и
  запись в `tavern-game/PITFALLS.md`.

## 3. Чинить в правильном порядке

1. Воспроизвести замером, а не глазами: проба, лог, `execute_code`.
2. Понять МЕХАНИЗМ, а не симптом. Три раза за сутки «предмет исчезает» имели
   три разные причины — шейдер, очередь отрисовки, альфа модели.
3. Починить.
4. Закрыть проверкой: тест, если правило про данные; проба, если про поведение.
5. Записать: правило — сюда, историю — в `PITFALLS.md`, находку — в коммит.

## 4. Частые ловушки редактора

- ⭐ **«Красное, а код не менялся» — сначала ПЕРЕКОМПИЛЯЦИЯ, потом разбор**
  (P269). Статические кэши переживают выход из play и держат уничтоженные
  Unity объекты: `KitMaterialsTests` падает с «слоты не прочитались: 0» на
  дереве, которое час назад было зелёным. `cycle.py compile` чистит домен.
  Если после этого зелено — чинить было нечего.
- «Тесты не стартуют» — Илья в play.
- «Правка не действует» — Unity отложил компиляцию (в play) или не импортировал
  ассет; проверить `isCompiling` и время сборки в `Library/ScriptAssemblies`.
- «Проба говорит не в play» — редактор вышел из play сам (перекомпиляция).
- «Слот всегда свободен / `InteractiveObject.All` = 0 / контейнер не видит содержимое» — редактор НЕ в play (кто-то вышел после твоей сборки): `All` заполняется только в play, спавн в edit mode молча «работает». Перед пробой — `cycle.py status`, в пробе — печатать `Application.isPlaying` (04.10, колода).
- Замер до/после снимать только когда сцену никто не трогает: чужая игра
  сдвигает предметы, и дифф покажет дрейф, а не правку.

## 5. Мост Unity MCP: проверка в начале сессии

Связь с редактором должна быть всегда, и её статус подсвечивается пользователю
явно (`✅ Unity MCP: connected` / `❌ Unity MCP: down` + причина). Делать вид,
что мост есть, когда его нет, — худшее из возможного: сессия начинает
«чинить» то, чего не видит.

```bash
claude mcp list 2>&1 | grep -i unity      # ждём "✔ Connected"
ss -ltn | grep -E ':8090|:8080'           # если не connected: слушает ли порт
curl -s -m3 -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<ПОРТ>/mcp
```

**Запасной путь (2026-08-30).** Если MCP-клиент сессии не подключился, а порт
слушает — мост доступен напрямую по HTTP, и это полноценная работа, а не
костыль:

```bash
python3 ~/.claude/skills/tavern-game/mcp_call.py execute_code '{"action":"execute","code":"return UnityEngine.Application.isPlaying;"}'
```

Статус в этом случае подсвечивать честно: `❌ клиент / ✅ мост по HTTP`.

### Ловушка: порт моста занят CockroachDB (2026-06-20)

MCP for Unity (CoplayDev, `f445f81`) работает по HTTP и по умолчанию хочет
порт **8080**, а на этой машине 8080 и 8081 держит CockroachDB рабочего
проекта Olimp-CMS. Мост порт не биндит, HTTP-сервера Unity нет, клиент стучится
в Cockroach и получает `404` на `/mcp`.

- **Решение:** окно **Window → MCP for Unity** → сменить порт на свободный
  (8090) → **Configure All Detected Clients** → перезапустить мост. Порты
  8080/8081 не трогать, это рабочий стек.
- В `~/.claude.json` для проекта должно стать
  `"UnityMCP": {"type":"http","url":"http://127.0.0.1:8090/mcp"}`. После правки —
  `/mcp` reconnect или рестарт сессии.
- **Скоуп:** сервер прописан локально под проект (`~/.claude.json` → projects →
  путь Tavern), сессии из других папок его НЕ видят. Чтобы видели — `--scope
  user` или `--scope project`.

Тот же класс ловушки есть у блендер-моста, но там порт занимает не чужой
сервис, а СВОЁ ЖЕ второе окно — P264 и `BLENDER.md`, чек-лист новой сцены.

## Офлайн-компиляция Roslyn и синтетические пробы постановки (03.10, P760/P761)

- `csc.dll @…rsp`: rsp брать самый свежий (`ls -t Library/Bee/artifacts/*/<сборка>.rsp | head -1`), иначе
  в нём удалённые соседями исходники (`CS2001`) и старые пакеты (`CS0006`). Проверяет ТОЛЬКО свою сборку:
  rsp сборки UI ссылается на `Library/ScriptAssemblies/Cozy.Grid.dll` редактора, новое поле Grid там не
  видно. Истина — компиляция редактора (`cycle.py compile`).
- ⭐ 04.10 (P856): зависимая сборка (Tavern.UI) ссылается на `Library/Bee/artifacts/*/Cozy.Grid.ref.dll` — подменять
  ЭТОТ путь на свою свежую `Cozy.Grid.dll` из скретчпада. Новые `.cs` соседей в rsp нет (CS0103 на чужих именах) —
  дописать недостающие файлы папки сборки; у rsp нет перевода строки в конце, перед дозаписью добавить `\n`, иначе путь
  склеится с `/additionalfile:…"`.
- Постановку в play доказывает только настоящий конвейер `ComputeObjectPose` (камера НИЖЕ перекрытия
  этажа, мышь через `InputSystem.QueueStateEvent` + `InputSystem.Update()`, герой в досягаемости) или глаза
  Ильи. Рефлексивный `ValidatePose` с сырым Y и `SurfaceSupported`/`OverlapsOthers` по отдельности —
  подсказка, не вердикт: они ждут уже разрешённую высоту.


## Офлайн-компиляция цепочкой (04.10, P800)

Когда правка задевает несколько сборок, а соседи параллельно меняют свои, одиночный `csc @rsp` врёт
(ref на старые соседние сборки, новые файлы соседей не в rsp). Рецепт, которым сессия ilya-83 04.10
проверяла каждую правку, Илья в play:

```bash
cd /media/ilya/T714/Unity/Tavern-fresh
B=Library/Bee/artifacts/2400b0aE.dag; S=<scratchpad>/oc; mkdir -p $S
DN=~/Unity/Hub/Editor/6000.3.10f1/Editor/Data/NetCoreRuntime/dotnet
CSC=~/Unity/Hub/Editor/6000.3.10f1/Editor/Data/DotNetSdkRoslyn/csc.dll
cp $B/*.ref.dll $B/*.UnityAdditionalFile.txt $S/
names="Cozy.Loc Cozy.View Cozy.Grid Cozy.Character Cozy.Effects Cozy.Weather Cozy.Cooking Cozy.Story Cozy.Combat Cozy.Creatures Tavern.Net Tavern.Core Tavern.UI Tavern.Tests.EditMode"
for a in $names; do sed "s#$B/#$S/#g" $B/$a.rsp > $S/$a.rsp; done   # выход и ref — в scratch
for pass in 1 2; do for a in $names; do $DN $CSC /nologo @$S/$a.rsp 2>&1 | grep " error "; done; done
```

- Порядок сборок — по зависимостям; второй проход добирает то, что упало из-за порядка.
- Новые `.cs` соседей, которых нет в rsp (редактор их ещё не компилировал): найти
  `for f in $(find Assets/Modules/Grid -name "*.cs"); do grep -q "$f" $S/Cozy.Grid.rsp || echo $f; done`
  и дописать в rsp строками `"путь"` С НОВОЙ СТРОКИ (последняя строка rsp без перевода строки — склейка).
- Без `UnityAdditionalFile.txt` рядом — `CS2001`. `MonoScriptInfoGenerator` warning `CS8785` — шум.
- Ошибка в чужом файле — сначала свежесть rsp/ref (P800), не чинить чужое.

## Пробы через мост и расчёт позы (03.10, P767)

`GridCursor.PosedBounds` и всё, что его зовёт (`SeatAlong`/`SeatBackToWall`, `ApplySeatSnap`, `ValidatePose`, `OverlapsOthers`), ставит ТЕЛО в позу и не возвращает: в игре это призрак, в пробе — живой объект уровня (выключатель уехал на y=0). Правило: сохранить `position/rotation`, вернуть в `finally`; проверять объекты только на этаже игрока — на чужом рендереры погашены гейтом и `PosedBounds` молча отдаёт `false`.
